An HTML page is elements inside elements: a heading, a paragraph, a list with items in it, a link inside each item. Each is an **opening tag**, some content, and a **closing tag**: `<h1>Shelf</h1>`. The tag text objects select an element's content, or the whole element, from anywhere inside it, so `cit` changes a heading's text without your finding the `>` that starts it.

Until now `/` has answered with JSON for programs. This lesson gives it a real page, `public/index.html`, that a browser shows, and you'll write and edit the page in Neovim.

## Tag objects: it and at

| Object | Selects |
|---|---|
| `it` | the content of the element around the cursor, between its opening and closing tags |
| `at` | the whole element, tags included |

- **The innermost element around the cursor.** In `<li><a href="https://neovim.io">Neovim</a></li>`, with the cursor on `Neovim`, `cit` changes the link's text. With the cursor on the `<li>` tag itself, the innermost element is the `li`, so `cit` replaces the whole link.
- **On a tag counts as inside it.** The cursor on any character of `<title>` or `</title>` selects that `title` element.
- **Across lines.** `dit` on a `<ul>` that spans several lines deletes every item, line breaks included, and leaves `<ul></ul>` on one line.
- **For a whole line, `dd` and `yy` are still the keys.** `dat` on an element that fills its line leaves the line behind, empty. Tag objects are for what's inside an element, and for elements that share a line with other text.
- A tag object works in any file whose elements are written as tags, HTML or not; the file type doesn't matter.

## A page at /

Shelf sends a page the way it sends JSON: a header saying what kind of content follows, then the content. The page's HTML lives in a file, so a small module reads it.

1. `:e server/pages.js` opens a new file. `i`, type it all, without leading spaces. Esc, `:w`.
2. `:e server/routes.js`. `2G`, `o`, and type `import { homePage } from './pages.js';` below the store's import. Esc.
3. In the table, the line `'GET /': home,`: `$`, `b` reaches `home`, and `ciw`, `homePage`, Esc. `:w`.

```javascript file=server/pages.js
// Shelf's web pages: HTML files from public/, sent as they are.
import fs from 'node:fs';

function sendPage(response, name) {
  response.setHeader('Content-Type', 'text/html; charset=utf-8');
  response.end(fs.readFileSync(new URL(`../public/${name}`, import.meta.url)));
}

export function homePage(request, response) {
  sendPage(response, 'index.html');
}
```

- **`text/html`** in the `Content-Type` header tells the browser to show the answer as a page, where `application/json` showed it as data.
- **`` new URL(`../public/${name}`, import.meta.url) ``** is the file's location, worked out from this file's as the data file's is in `store.js`: `public/index.html` when `name` is `'index.html'`.
- **`fs.readFileSync(location)`** without `'utf8'` gives the file's raw bytes, which `response.end` sends unchanged. There's nothing to parse: the page goes out as it is on disk.
- **`sendPage`** isn't exported. **`homePage`** is the handler, used in the routes table like any other.
- `/api` still answers with `home`'s JSON, for programs that want the list of routes.

```check
run "out=$(PORT=3917 node server/server.js & sleep 1; curl -s -m 2 -i http://localhost:3917/; kill $!); echo \"$out\"" stdout="Content-Type: text/html; charset=utf-8" label="/ answers with an HTML Content-Type" -- server/pages.js sends the text/html header; the table's 'GET /' line must name homePage, and routes.js must import it from './pages.js'.
run "out=$(PORT=3917 node server/server.js & sleep 1; curl -s -m 2 http://localhost:3917/api; kill $!); echo \"$out\"" stdout="\"name\":\"shelf\"" label="/api still answers with home's JSON" -- Only the 'GET /' line changes; 'GET /api': home, stays.
```

## Write the page

`:e public/index.html`, the empty page from the starter project. `i`, and type the page, Enter after each line, **without** leading spaces: Neovim indents HTML by itself, each element inside another one level further in, and moves each closing tag back out. Esc, `:w`.

```html file=public/index.html
<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8">
    <title>Shelf</title>
  </head>
  <body>
    <h1>Shelf</h1>
    <p>Your bookmarks, kept on your own computer.</p>
    <ul id="bookmarks">
      <li><a href="https://neovim.io">Neovim</a></li>
    </ul>
  </body>
</html>
```

- **`<!doctype html>`** tells the browser this is modern HTML.
- **`<html lang="en">`** holds everything else; `lang` says the page is in English.
- **`<head>`** is about the page: **`<meta charset="utf-8">`** says how its text is encoded, and **`<title>`** is the name on the browser's tab.
- **`<body>`** is what's shown: a heading (**`<h1>`**), a paragraph (**`<p>`**), and a list (**`<ul>`**, an unordered list) of items (**`<li>`**).
- **`<a href="…">`** is a link: `href` is where it goes, and the text between the tags is what you click. **`id="bookmarks"`** names the list, so that later chapters' code can find it.
- `<meta>` has no closing tag: it has no content.

Restart the server and open `http://localhost:3000` in your browser: the heading, the sentence, and one link.

```check
run "out=$(PORT=3917 node server/server.js & sleep 1; curl -s -m 2 http://localhost:3917/; kill $!); echo \"$out\"" stdout="<h1>Shelf</h1>" label="the page has the Shelf heading" -- public/index.html needs <h1>Shelf</h1> inside <body>.
run "out=$(PORT=3917 node server/server.js & sleep 1; curl -s -m 2 http://localhost:3917/; kill $!); echo \"$out\"" stdout="      <li><a href=\"https://neovim.io\">Neovim</a></li>" label="the list holds the Neovim link, indented three levels" -- Type each line without leading spaces and let Neovim indent it; the li line ends up six spaces in.
run "sed -n 5p public/index.html | grep -Fqx '    <title>Shelf</title>'" label="the title is the fifth line, inside <head>" -- Line 5: <title>Shelf</title>, after the meta line.
```

## A second link, with ci" and cit

Add Vim's site below Neovim's. Put the cursor on the `<li>` line and `yyp`: a whole line is still `yy`'s job. The copy's cursor starts on its `<`. First, the mistake:

- `cit`, `Vim`, Esc. The line is now `<li>Vim</li>`: the cursor was on the `li`'s tag, so its content, the whole link, was replaced. `:w` and reload the page: the second item is plain text, not a link.
- **How to find it**: in the browser the item isn't blue and underlined, and in the file the `<a …>` is gone. When `cit` takes more than you meant, the cursor was on an outer element: check which tag the cursor was in or on.

`u` brings the link back. Now do it from inside:

1. `f:` lands on the `:` in `https://`, inside the `href` string. `ci"`, `https://www.vim.org`, Esc.
2. `fN` finds the `N` of `Neovim`, inside the link's text. `cit`, `Vim`, Esc. `:w`.

```html file=public/index.html
<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8">
    <title>Shelf</title>
  </head>
  <body>
    <h1>Shelf</h1>
    <p>Your bookmarks, kept on your own computer.</p>
    <ul id="bookmarks">
      <li><a href="https://neovim.io">Neovim</a></li>
      <li><a href="https://www.vim.org">Vim</a></li>
    </ul>
  </body>
</html>
```

Reload the page: two links. These two are typed into the page; a later chapter fills the list from `/api/bookmarks` instead.

```check
run "out=$(PORT=3917 node server/server.js & sleep 1; curl -s -m 2 http://localhost:3917/; kill $!); echo \"$out\"" stdout="<li><a href=\"https://www.vim.org\">Vim</a></li>" label="the second item links to https://www.vim.org, with the text Vim" -- On the copied line: ci" from inside the href, then cit from inside the link's text.
run "test $(grep -c '<li>' public/index.html) -eq 2 && grep -Fq '<li><a href=\"https://neovim.io\">Neovim</a></li>' public/index.html" label="there are two items, and the Neovim one is unchanged" -- yyp copies the line; change only the copy.
```

| Keys | Does |
|---|---|
| `cit` / `dit` / `yit` | change / empty / copy an element's content, from anywhere inside it or on its tags |
| `cat` / `dat` | the same for the whole element, tags included |

That completes chapter 4. Every operator from chapter 3 now works on whole things as well as on motions: words and WORDs, paragraphs, strings, brackets and elements, from wherever the cursor happens to be inside them. Shelf has a store, `POST` and `DELETE` routes that refuse bad requests, and a page. Chapter 5 is **search**: `/` to jump to any text in a file, `*` for the word under the cursor, `cgn` and `.` to change match after match (VS Code's multi-cursor, done Neovim's way), and `:s` to replace across a whole file.
