Kit has three tools, and each says "read this file, or standard input" in its own way. `count.py` reads standard input when given `-` or nothing; `hexdump.py` the same, with slightly different code; and `filter.py` insists on a file name. `count` pulls `--json` out of its arguments with one line, and if `hexdump` wanted `--json` too, it would grow its own copy. Copies drift apart: fix a bug in one and the others keep it. This lesson starts module 1.5, on what happens when a function is called. It gives Kit its first **shared module**, a file of functions that several tools import, and on the way it looks hard at calls themselves: what a parameter is, what comes back, when each part of a call is evaluated, where names live and for how long. And it springs one of Python's best-known traps, a default value that remembers.

- Predict the order in which a call's parts are evaluated, and when a default value is evaluated.
- Say which names a function can see, and how long a name and its object live, including names in an imported module.
- Recognise the mutable-default trap from its evidence, explain it, and write the safe form.

## One way to say "a file"

A **module** is just a Python file. Another file can **import** it, `from kitargs import take_flag`, and then call its functions as if it had written them. The first module holds two functions that Kit's tools all need:

- `take_flag(args, flag)` takes one flag, such as `--json`, out of the arguments. It returns two things: whether the flag was there, and the rest of the arguments.
- `open_input(name)` returns what a tool should read: standard input for `-` or no name, otherwise the named file, opened for bytes.

Some words, since this module is about calls. In `def take_flag(args, flag, rest=[]):`, the names `args`, `flag` and `rest` are **parameters**: names that the function's body uses. In a call, `take_flag(["notes.txt", "--json"], "--json")`, the values passed are **arguments**. Calling the function binds each parameter to its argument, the way an assignment would (01-04-01's call by sharing). `rest=[]` gives `rest` a **default value**, used when a call passes no argument for it. Here it lets a caller pass its own list to collect into.

A function returns exactly one object. `return found, rest` returns a **tuple**, `(found, rest)` (01-04-02), and the caller can unpack it into two names: `as_json, args = take_flag(…)`. A function that ends without a `return` returns `None`.

**This version has one flaw. Don't fix it yet; it won't show up today.**

```python file=kit/kitargs.py
import sys


# Take one flag out of a list of command-line arguments. Returns two things:
# whether the flag was there, and the other arguments, in order. A caller can
# pass its own list as rest to collect them into.
def take_flag(args, flag, rest=[]):
    found = False
    for arg in args:
        if arg == flag:
            found = True
        else:
            rest.append(arg)
    return found, rest


# The input a tool should read: standard input for "-" or no name at all,
# otherwise the named file, opened for reading bytes.
def open_input(name):
    if name is None or name == "-":
        return sys.stdin.buffer
    return open(name, "rb")
```

## count uses the module

Now `count.py` uses it. Its `main` loses the `--json` comprehension and the two ways of opening its input:

- `as_json, args = take_flag(sys.argv[1:], "--json")` unpacks the two results.
- `with open_input(name) as stream:` uses whatever `open_input` returned. A `with` closes the stream at the end of the block. For standard input that's harmless here, since the program reads it only once and ends soon after.
- At the top, `from kitargs import open_input, take_flag`. Python finds `kitargs.py` because it's in the same folder as `count.py`: the folder of the script being run is always on the list of places Python looks.

```python file=kit/count.py
import codecs
import json
import sys

from kitargs import open_input, take_flag

# ASCII whitespace, the six bytes from the definition of a word.
WHITESPACE = b" \t\n\r\x0b\x0c"
NEWLINE = 10  # the value of the byte b"\n"
CHUNK_SIZE = 65536  # how many bytes to read at a time


# The counting as a state machine, fed one piece at a time.
def start(encoding):
    return {
        "bytes": 0,
        "newlines": 0,
        "words": 0,
        "in_word": False,
        "last": None,
        "line_length": 0,
        "longest": 0,
        "characters": 0,
        "decoder": codecs.getincrementaldecoder(encoding)(),
    }


def feed(state, chunk):
    in_word = state["in_word"]
    words = state["words"]
    for byte in chunk:
        if byte in WHITESPACE:
            in_word = False
        elif not in_word:
            in_word = True
            words += 1
    line_length = state["line_length"]
    longest = state["longest"]
    for byte in chunk:
        if byte == NEWLINE:
            longest = max(longest, line_length)
            line_length = 0
        else:
            line_length += 1
    last = state["last"]
    if chunk:
        last = chunk[-1]
    characters = state["characters"]
    decoder = state["decoder"]
    if decoder is not None:
        try:
            characters += len(decoder.decode(chunk))
        except UnicodeDecodeError:
            characters = None
            decoder = None
    return {
        "bytes": state["bytes"] + len(chunk),
        "newlines": state["newlines"] + chunk.count(b"\n"),
        "words": words,
        "in_word": in_word,
        "last": last,
        "line_length": line_length,
        "longest": longest,
        "characters": characters,
        "decoder": decoder,
    }


def finish(state):
    lines = state["newlines"]
    if state["last"] is not None and state["last"] != NEWLINE:
        lines += 1
    characters = state["characters"]
    if state["decoder"] is not None:
        try:
            characters += len(state["decoder"].decode(b"", final=True))
        except UnicodeDecodeError:
            characters = None
    return {
        "bytes": state["bytes"],
        "lines": lines,
        "words": state["words"],
        "characters": characters,
        "longest": max(state["longest"], state["line_length"]),
    }


# The counting as a function: all the bytes in, counts out.
def measure(data, encoding):
    return finish(feed(start(encoding), data))


# Read a stream a piece at a time, feeding each piece to the machine.
def count_stream(stream, encoding):
    state = start(encoding)
    while True:
        chunk = stream.read(CHUNK_SIZE)
        if not chunk:
            break
        state = feed(state, chunk)
    return finish(state)


# The program: read the input, count it, print the result.
def main():
    as_json, args = take_flag(sys.argv[1:], "--json")

    if len(args) > 1:
        encoding = args[1]
    else:
        encoding = "utf-8"

    name = None
    if len(args) > 0:
        name = args[0]
    with open_input(name) as stream:
        counts = count_stream(stream, encoding)

    if as_json:
        print(json.dumps(counts))
        return
    print("bytes:", counts["bytes"])
    print("lines:", counts["lines"])
    print("words:", counts["words"])
    if counts["characters"] is None:
        print("characters: not", encoding, "text")
    else:
        print("characters:", counts["characters"])
    print("longest:", counts["longest"])


if __name__ == "__main__":
    main()
```

## A list that remembers

Each run of `count.py` calls `take_flag` once, and everything works. Now call it twice in one program, as a test, or a tool with two flags, would:

```
.venv/bin/python -c "from kitargs import take_flag; print(take_flag(['a', '--json'], '--json')); print(take_flag(['b'], '--json'))"
```

```predict
question: The second call is given only ['b']. What will it print?
choice: (False, ['b'])
choice: (False, ['a', 'b'])
choice: (True, ['b'])
answer: (False, ['a', 'b'])
explain: The second call's rest list still holds 'a' from the first call. Neither call passed a rest, so both used the default, and the default is one list, made once, when def ran. The first call appended 'a' to it; the second appended 'b' to the same list. A function's default value is an object that lives as long as the function does.
```

It prints `(True, ['a'])` and then `(False, ['a', 'b'])`. The second call returned an argument it was never given. Find out where it came from. A function keeps its default values in `__defaults__`, a tuple with one entry per default. Ask for it after the two calls:

```
.venv/bin/python -c "from kitargs import take_flag; take_flag(['a'], '-q'); take_flag(['b'], '-q'); print(take_flag.__defaults__)"
```

It prints `(['a', 'b'],)`. That's the evidence. The default isn't "a new empty list each time": it is one particular list. Python evaluates a default once, when the `def` statement runs, and stores the object it got. Each call that doesn't pass `rest` binds `rest` to that same object, and `rest.append` changes it in place (01-04-02), for every later call. On the command line it hid, because each run is a new process with a fresh function.

The safe form is a default that can't change. Python programmers use `None`, which means "not given", and make the new list inside the call, where it is made fresh every time:

```python file=kit/kitargs.py
import sys


# Take one flag out of a list of command-line arguments. Returns two things:
# whether the flag was there, and the other arguments, in order. A caller can
# pass its own list as rest to collect them into; otherwise each call makes
# a new one.
def take_flag(args, flag, rest=None):
    if rest is None:
        rest = []
    found = False
    for arg in args:
        if arg == flag:
            found = True
        else:
            rest.append(arg)
    return found, rest


# The input a tool should read: standard input for "-" or no name at all,
# otherwise the named file, opened for reading bytes.
def open_input(name):
    if name is None or name == "-":
        return sys.stdin.buffer
    return open(name, "rb")
```

Save it and run both commands again: `(True, ['a'])`, `(False, ['b'])`, and the defaults are `(None,)`. Passing a list of your own still collects into it: `take_flag(['y'], '-q', mine)` appends `'y'` to `mine`.

The rule: **never use a mutable object (a list, a dictionary, a set) as a default value.** Numbers, strings, `None` and tuples are safe, because nothing can change them. Linters warn about this (module 1.6), and JavaScript doesn't have the trap: it evaluates a default each time a call needs it.

```check
run "cd kit; .venv/Scripts/python -c \"from kitargs import take_flag; take_flag(['a'], '-q'); print(take_flag.__defaults__)\"" stdout="(None,)" -- take_flag's default should be None, which nothing can change.
run "cd kit; .venv/Scripts/python -c \"from kitargs import take_flag; mine = ['x']; print(take_flag(['y'], '-q', mine), mine)\"" stdout="(False, ['x', 'y']) ['x', 'y']" -- A list passed as rest should still be collected into.
```

## When things are evaluated, and where names live

The trap came from *when* a default is evaluated. This file makes the timing of a call visible, and shows one more rule about which names a function sees:

- `shout(word)` prints as it's evaluated, so you can see when an argument is worked out.
- `stamp(when=shout("the default"))` has a default that is a call, so you can see when the default is evaluated.
- `add_one` tries to change a module-level name.

```python file=kit/order.py
# When things are evaluated, and which names a function can see.


def shout(word):
    print("evaluating", word)
    return word


def pair(a, b):
    print("calling pair")
    return (a, b)


# 1. Arguments are evaluated, left to right, before the call begins.
print(pair(shout("left"), shout("right")))


# 2. A default value is evaluated once, when def runs: not at each call.
def stamp(when=shout("the default")):
    return when


print("defined stamp")
print(stamp(), stamp())

# 3. A name assigned anywhere in a function is local to the whole function.
total = 0


def add_one():
    total = total + 1
    return total


try:
    add_one()
except UnboundLocalError as error:
    print("UnboundLocalError:", error)
```

```predict
question: Which line will order.py print first?
choice: calling pair
choice: evaluating left
choice: evaluating right
answer: evaluating left
explain: Before a function is called, its arguments are evaluated, left to right. So shout("left") runs first and prints "evaluating left", then shout("right"), and only then does pair start and print "calling pair". The call is the last thing to happen, not the first.
verify: cd kit; .venv/Scripts/python order.py
```

Save it and run `.venv/bin/python order.py`:

```
evaluating left
evaluating right
calling pair
('left', 'right')
evaluating the default
defined stamp
the default the default
UnboundLocalError: cannot access local variable 'total' where it is not associated with a value
```

1. **Arguments first, left to right, then the call.** In `f(a(), b())`, `a()` runs before `b()`, and both before `f`. (Python and JavaScript both promise this order. C and C++ famously don't, for arguments.)
2. **Defaults when `def` runs.** "evaluating the default" appears before "defined stamp", and only once, although `stamp` is called twice: that's `take_flag`'s trap, seen directly.
3. **Scope.** Inside a function, a name that the function *assigns to* anywhere in its body is **local** to that function: a new name that exists only during the call, separate from any name outside. `add_one` assigns `total`, so `total` is local throughout `add_one`, including on the right of `total = total + 1`, where it has no value yet. Hence the `UnboundLocalError`. (The message's wording varies between Python versions.) A function that only *reads* a name, without assigning it, sees the module's name. Python has a `global` statement to say "I mean the module's `total`", but code that changes module-level names from inside functions is hard to follow (01-04-03's table on globals); returning a new value is almost always better.

**Lifetime.** A local name lives for one call: when the function returns, its names are gone, and the objects they referred to live on only if something else still refers to them, such as a return value. A module's names live as long as the program, because the module is kept in `sys.modules`. So a module-level list, or a default value, is shared by every caller, for the whole run: exactly what `rest=[]` was.

**What else, and why not.** Other ways to share code between Kit's tools, and what each costs:

| Way | Cost |
|---|---|
| Copy the code into each tool, as before this lesson | Simple, and each tool stands alone; every fix must be made in every copy, and they drift apart |
| One shared module beside the tools, as here | One place to fix; the tools must be run from files in the same folder as the module, or Python won't find it |
| A package (a folder with several modules) installed into the virtual environment | Found from anywhere, and the usual shape for real tools; needs packaging (01-06-05) |
| A command-line library such as the standard `argparse` | Handles flags, help text and errors properly; more to learn than two small functions, and 01-06 is a better place for it |

## What you can do now

- **Parameters** are a function's names; **arguments** are the values a call passes; a call binds one to the other. A function returns one object: a tuple for several values, `None` if it never says.
- A call's **arguments are evaluated left to right, before the call**. A **default value is evaluated once, when `def` runs**, and the same object is used by every call that needs it.
- So a **mutable default** (`rest=[]`) collects across calls. Use `None` and make the object inside the call.
- **Scope:** a name assigned anywhere in a function is local to that function, for the whole body; reading a module's name works, assigning it makes a new local. **Lifetime:** locals last one call; a module's names, and its defaults, last the whole run.
- A **module** is a file that others import. It runs once, and is shared by every importer through `sys.modules`. Shared code in one module means one place to fix.

```predict
question: A teammate writes def log(message, history=[]): history.append(message); return history. A web server calls log("start") once for each request. What does the hundredth request's call return, and why might nobody notice for weeks?
explain: A list of all hundred messages, and it keeps growing for as long as the server runs: the default list was made once, when the module was imported, and every call appends to the same one. Nobody notices because each test, and each short command-line run, starts a new process with a new, empty list, so the first call always looks right. The symptom appears only in a long-running process, as slowly growing memory or one request seeing another's data. The fix is history=None, and history = [] inside.
```
