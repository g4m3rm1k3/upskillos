### The story so far

Until now, the browser’s important data came from the person or this device. Book search asks another system for data across a network. That introduces latency, availability, response formats and trust boundaries.

We will first build the API function without a screen. You already know functions, validation and tests with substitute collaborators. The new concept is an operation whose result arrives later.

## Convert a network response into app data

### Request, response and a receipt

A restaurant-order analogy is useful: you submit a request, receive an acknowledgment, then wait for the result. A Promise is like a receipt for an eventual outcome, not the meal itself. It can be pending, fulfilled with a value, or rejected with a reason.

The analogy has limits. An HTTP response with status 404 is still a completed response, not necessarily a rejected fetch promise. You must inspect what the server actually sent.

```text
query text → encoded URL → fetch → Response
                               ├─ not ok → application error
                               └─ ok → parse JSON → validate shape → normalized books
```

`await` suspends this async function’s continuation until its promise settles. Other browser work can continue. It does not make the network synchronous or stop a person from submitting another query.

An async function returns a Promise: a value that will settle later. await pauses this function until the promise settles, without blocking the entire page. fetch rejects for network failure, but an HTTP 404 or 429 still returns a response: check ok. URLSearchParams encodes spaces and special characters. Request only the fields you use. signal will let the UI cancel obsolete requests. CORS is the remote server’s browser access policy; do not disable browser security or use an unknown proxy to bypass it.

```javascript file=books/api.mjs
export async function searchBooks(query, request = fetch, signal) {
  const text = query.trim();
  if (!text) return [];
  const url = new URL('https://openlibrary.org/search.json');
  url.searchParams.set('q', text);
  url.searchParams.set('fields', 'key,title,author_name');
  url.searchParams.set('limit', '10');
  const response = await request(url, { signal });
  if (!response.ok) throw new Error(`Search failed (${response.status}). Try again.`);
  const data = await response.json();
  if (!data || !Array.isArray(data.docs)) throw new Error('Unexpected search response');
  return data.docs.filter(book => book && typeof book.key === 'string' && typeof book.title === 'string').map(book => ({
    id: book.key,
    title: book.title,
    author: Array.isArray(book.author_name) ? book.author_name.filter(name => typeof name === 'string').join(', ') : 'Unknown author'
  }));
}
```

### Read each boundary in the client

`query.trim()` removes surrounding whitespace. An empty query returns an empty array without making a request. A nonempty query is placed into URLSearchParams, which treats `A&B` as one value instead of mistaking the ampersand for a second parameter separator.

`request = fetch` is a default parameter. In the real app, an omitted request argument uses fetch. In tests, a fake function can replace it. This also avoids making the model depend on a particular test framework.

`response.ok` covers successful HTTP statuses. The client throws on 429 rather than pretending rate limiting means no matching books. Next, `response.json()` is also asynchronous and can fail if the body is not valid JSON. After parsing, we still check that docs is an array.

Finally, map translates the provider’s names into our own compact shape: id, title and author. This is normalization. If the provider later changes an optional field, the rest of our app need not know all the provider’s details. A missing author becomes a deliberate display fallback, not the word undefined.

**Rule of thumb:** validate and normalize at external boundaries, then let internal components consume a small documented shape. Do not spread raw API objects throughout every component merely because all their fields are available.

## Test without depending on the internet

The default request is fetch, but tests pass fake functions with known results. This is dependency injection: choose a collaborator at the boundary. A fixture is controlled example data. The query A&B must stay one value, not become another URL parameter. Run node books/api.test.mjs.

```javascript file=books/api.test.mjs
import assert from 'node:assert/strict';
import { searchBooks } from './api.mjs';
let seen;
const fake = async url => {
  seen = url;
  return { ok: true, json: async () => ({ docs: [{ key: '/works/1', title: 'A Book' }] }) };
};
assert.deepEqual(await searchBooks(' A&B ', fake), [{ id: '/works/1', title: 'A Book', author: 'Unknown author' }]);
assert.equal(seen.searchParams.get('q'), 'A&B');
assert.deepEqual(await searchBooks(' ', fake), []);
await assert.rejects(searchBooks('x', async () => ({ ok: false, status: 429 })), /429/);
console.log('API contract passed');
```

### A fake response answers one precise question

The test’s fake request captures the URL and returns a response-shaped object. Its async json method supplies fixed data. That lets the test ask whether query encoding and missing-author handling work regardless of the current catalog contents or internet connection.

It does not establish that Open Library is currently reachable, that CORS permits the live call in every environment, or that every future response shape is supported. A separate live smoke check addresses connectivity; deterministic contract tests address your transformation logic.

Retry only with a policy. Repeating a failed GET can be reasonable, but automatic rapid retries against a 429 response worsen rate limiting. This course uses an explicit resubmit action so the person can decide when to try again.
