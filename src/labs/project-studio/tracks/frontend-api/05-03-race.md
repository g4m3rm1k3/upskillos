Outcome: reproduce an asynchronous race with controlled promises instead of hoping for a slow network. A race occurs when output depends on which operation finishes first. Correct behavior depends on the latest user intent, not the most recent network completion.

## Walk the timeline

Before trying this step, make a prediction.

```predict

choice: No
choice: Yes
answer: No
explain: A separate sequence guard prevents stale results even without cooperative cancellation.
```

On paper write: submit A (ticket 1), submit B (ticket 2), B resolves, A resolves. At A’s completion ticket !== sequence, so the handler returns before touching the list. Cancellation saves resources, while the sequence guard establishes correctness even with a request implementation that ignores abort. Repeat the timeline for A failing after B succeeds.
