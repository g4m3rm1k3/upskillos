A release is a reproducible result with evidence, configuration and a recovery plan. “It ran in my editor” leaves the environment and exact source ambiguous. We build frontend assets before packaging the Java archive so the release contains the interface learners actually tested.

## Declare repeatable CI preparation

CI starts from a checkout instead of your working directory. The runner image supplies tooling, while setup actions select the language runtimes. Read-only repository permissions are sufficient for verification. Dependency caching improves speed; it must not be required for correctness.

Major action tags are readable teaching references but can move; a stricter supply-chain policy pins reviewed commit hashes and automates updates. That choice trades auditability against maintenance effort.

Type this fragment yourself. Start an empty file at `.github/workflows/verify.yml`:

```yaml edit=.github/workflows/verify.yml mode=replace
name: Verify Common Ground
on: [push, pull_request]
permissions:
  contents: read
jobs:
  verify:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with:
          distribution: temurin
          java-version: '21'
      - uses: actions/setup-node@v4
        with:
          node-version: '22.14.0'
          cache: npm
          cache-dependency-path: frontend/package-lock.json
```

## Build in dependency order

The lockfile must be committed for npm ci. The frontend build writes static assets before Maven packages resources. Verify runs tests and packaging lifecycle stages; -B selects noninteractive output. The artifact is the output to deploy, not a fresh rebuild from an unknown checkout.

Append `src/main/resources/static/app/` to .gitignore because these files are generated by the frontend build. Commit source and lockfiles, not the generated assets. Run these same commands locally before pushing your learning repository.

Type this fragment yourself. Append to `.github/workflows/verify.yml`:

```yaml edit=.github/workflows/verify.yml mode=append
      - run: npm ci --prefix frontend
      - run: npm test --prefix frontend
      - run: npm run build --prefix frontend
      - run: mvn -B verify
      - uses: actions/upload-artifact@v4
        with:
          name: common-ground
          path: target/common-ground-1.0.0.jar
```

```check
run "npm run build --prefix frontend" timeout=180
run "mvn -q verify" timeout=180
```

## Run the packaged application

Stop the development server. With your local WORKSPACE_PASSWORD set, run:

```text
java -jar target/common-ground-1.0.0.jar
```

Open `/login`, sign in, and visit `/app/`. Create a task, advance it, add a comment, restart and verify persistence. Inspect the built asset paths in the Network panel. A working Vite development server does not prove packaged asset paths are correct.

Before deploying elsewhere, decide TLS termination, secret injection, database ownership, backups, log retention, resource limits and dependency patch policy. The bundled H2 database is for this local learning release. A hosted shared service needs an explicit database and identity deployment design.

Record the Git commit, build commands and observed smoke test in `operations/release.md`. Stop the process when done.
