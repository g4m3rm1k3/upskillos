You've learned CSS on the portfolio. This lesson is the other half: how it's applied to an application's interface, where the needs are different. A content page wants generous space and big type; a spreadsheet wants as many cells on screen as possible, lined up exactly, with grid lines that are there without shouting.

## Link a stylesheet

Add one line to the `<head>` of `index.html`, under the title:

```html file=index.html
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="utf-8">
    <title>Spreadsheet</title>
    <link rel="stylesheet" href="style.css">
  </head>
  <body>
    <h1>Spreadsheet</h1>
    <table>
      <thead>
        <tr>
          <th></th>
          <th>A</th>
          <th>B</th>
          <th>C</th>
          <th>D</th>
        </tr>
      </thead>
      <tbody>
        <tr>
          <th>1</th>
          <td>Item</td>
          <td>Price</td>
          <td>Qty</td>
          <td>Total</td>
        </tr>
        <tr>
          <th>2</th>
          <td>Coffee</td>
          <td>3.50</td>
          <td>2</td>
          <td></td>
        </tr>
        <tr>
          <th>3</th>
          <td>Bagel</td>
          <td>2.25</td>
          <td>3</td>
          <td></td>
        </tr>
        <tr>
          <th>4</th>
          <td>Tea</td>
          <td>2.75</td>
          <td>1</td>
          <td></td>
        </tr>
        <tr>
          <th>5</th>
          <td></td>
          <td></td>
          <td></td>
          <td></td>
        </tr>
      </tbody>
    </table>
  </body>
</html>
```

`<link>` connects another file to the page. `rel="stylesheet"` says what kind of connection it is, and `href="style.css"` names the file. `href` is a **relative path** (lesson 0.1): relative to the folder `index.html` is in.

```check
contains index.html "<link rel=\"stylesheet\" href=\"style.css\">" -- Add the <link> line inside <head>.
```

## The stylesheet

This step opens `style.css`. Start with the grid itself: lines between the cells, and cells of an even size.

```css file=style.css
body {
  font-family: system-ui, sans-serif;
  margin: 24px;
}

table {
  border-collapse: collapse;
}

th,
td {
  border: 1px solid #d0d7de;
  padding: 4px 8px;
  min-width: 80px;
  height: 24px;
  font-size: 13px;
}
```

Refresh the browser: a grid of lines.

- **`border-collapse: collapse`** makes neighbouring cells share one border line instead of each drawing its own. Without it, every cell has a double outline, and the grid looks like a sheet of stamps. Try it: delete that line, refresh, and look closely at the lines. Then put it back.
- **`th, td`** gives every cell, header or data, the same border, padding and size, so the grid's lines run straight across and down.
- **Sizes in `px` here, deliberately.** The portfolio used `rem` so text grows with the reader's setting. Dense application interfaces (spreadsheets, code editors) often fix their sizes, because cells must line up exactly and as many as possible must fit on screen; they offer their own zoom instead. It's a trade-off, and Sprint 12 revisits it with a real design system.
- **A quiet grid line**, `#d0d7de`, a light blue-grey: the data, not the grid, should be what stands out.

```check
file style.css
page index.html "getComputedStyle(document.querySelector('table')).borderCollapse" collapse label="the table's borders collapse into single lines"
page index.html "getComputedStyle(document.querySelector('td')).borderTopStyle" solid label="data cells have a solid border"
```

## Shaded headers {#headers}

The column letters and row numbers aren't data, and they should look different. Add a rule for header cells:

```css file=style.css
body {
  font-family: system-ui, sans-serif;
  margin: 24px;
}

table {
  border-collapse: collapse;
}

th,
td {
  border: 1px solid #d0d7de;
  padding: 4px 8px;
  min-width: 80px;
  height: 24px;
  font-size: 13px;
}

th {
  background: #f3f4f6;
  color: #57606a;
  font-weight: 600;
}
```

`th` matches header cells only. Both this rule and `th, td` apply to them, but they set different properties, so headers get both: the border and size from one, the shading from the other. Grey text on a pale grey (`#57606a` on `#f3f4f6`) is quieter than the data's black, and still 5.81 : 1, comfortably readable.

```check
page index.html "getComputedStyle(document.querySelector('thead th')).backgroundColor" "rgb(243, 244, 246)" label="header cells are shaded"
page index.html "getComputedStyle(document.querySelector('td')).backgroundColor" "rgba(0, 0, 0, 0)" label="data cells aren't"
```

## Column letters that stay put {#sticky}

When a sheet has more rows than fit on the screen, the column letters scroll away with them. Keep them at the top:

```css file=style.css
body {
  font-family: system-ui, sans-serif;
  margin: 24px;
}

table {
  border-collapse: collapse;
}

th,
td {
  border: 1px solid #d0d7de;
  padding: 4px 8px;
  min-width: 80px;
  height: 24px;
  font-size: 13px;
}

th {
  background: #f3f4f6;
  color: #57606a;
  font-weight: 600;
}

thead th {
  position: sticky;
  top: 0;
}
```

Before you refresh, one selector to think about:

```predict
question: The new rule's selector is `thead th`. Which cells does it make sticky?
choice: The column letters (and the empty corner)
choice: Every header cell, the row numbers too
choice: Every cell in the table
answer: The column letters (and the empty corner)
explain: A space means "inside" (Styling 2): `thead th` is every `th` inside the `<thead>`, which is the header row. The row numbers are `th`s too, but they're inside `<tbody>`, so this rule doesn't reach them.
verify: page index.html "getComputedStyle(document.querySelector('tbody th')).position === 'sticky' ? 'Every header cell, the row numbers too' : 'The column letters (and the empty corner)'"
```

**`position: sticky; top: 0`** keeps an element in its place in the page until scrolling would carry it past the top of the window, and then holds it there. With 5 rows nothing scrolls yet; with 100 rows in sprint 3, you'll see the letters stay put.

```check
page index.html "getComputedStyle(document.querySelector('thead th')).position" sticky label="the column headers are sticky"
page index.html "getComputedStyle(document.querySelector('tbody th')).position" static label="the row numbers are not sticky"
```

## Your turn: the sheet's colours as tokens

The stylesheet writes three colours directly into its rules, and the grid-line colour will soon be needed in more places (sprint 3 adds boxes above the grid in the same colour). Make them **design tokens**, as in Styling 3 and 4: custom properties on `:root`, named for their **role** (what they're for, not what colour they are), used with `var(...)`.

The sheet must look exactly the same afterwards. Commit when it's done.

```check
page index.html "[...document.styleSheets].some((sheet) => [...sheet.cssRules].some((rule) => rule.selectorText === ':root' && [...rule.style].some((name) => name.startsWith('--'))))" true server=static label="colour tokens are defined on :root" -- Add a :root rule with a custom property for each colour.
run "node -e \"console.log(require('fs').readFileSync('style.css', 'utf8').split('#d0d7de').length - 1)\"" stdout="1" label="the grid-line colour is written only once, in its token" -- Replace #d0d7de in the rules with var(--your-token-name).
contains style.css "var(--" label="the rules read the tokens with var()"
page index.html "getComputedStyle(document.querySelector('td')).borderTopColor" "rgb(208, 215, 222)" label="grid lines are the same colour as before" -- Check your var(...) names match the tokens exactly.
page index.html "getComputedStyle(document.querySelector('thead th')).backgroundColor + ' ' + getComputedStyle(document.querySelector('thead th')).color" "rgb(243, 244, 246) rgb(87, 96, 106)" label="headers look the same as before"
git-clean -- Commit it: git commit -am "Name the sheet's colours as tokens"
```

```hints
nudge: The portfolio's `:root` rule is the model: a list of `--name: value;` lines, then rules that say `var(--name)`.
concept: A token is named for its job, so the name still makes sense if the colour changes: `--grid-line` rather than `--light-blue`. Custom properties set on `:root` are inherited by every element, so any rule can read them.
shape: A `:root` rule at the top with three tokens, then each colour in the rules replaced by `var(...)` of its token.
answer: ~~~css
:root {
  --grid-line: #d0d7de;
  --header-bg: #f3f4f6;
  --header-text: #57606a;
}
~~~
Then `border: 1px solid var(--grid-line);` in `th, td`, and `background: var(--header-bg);` and `color: var(--header-text);` in `th`.
```
