You need a web server for your page. You could write one, but professionals reach for a ready-made tool, and the one this series uses is **Vite** (French for "fast", said *veet*). It serves your files, reloads the browser when you save, and later packages the app for release.

Vite is a **package**: someone else's code, published for anyone to use. JavaScript packages are installed with **npm**, which came with Node in lesson 0.3. It's to JavaScript what `pip` is to Python, with one big difference you'll see in a moment: packages are installed **into your project**, not into your computer.

## package.json

npm keeps a project's settings and its list of packages in a file called `package.json`. Make one:

```powershell
npm init -y
```

```text
PS C:\Users\you\Documents\spreadsheet> npm init -y
Wrote to C:\Users\you\Documents\spreadsheet\package.json:

{
  "name": "spreadsheet",
  "version": "1.0.0",
  "description": "",
  "main": "columns.js",
  "scripts": {
    "test": "echo \"Error: no test specified\" && exit 1"
  },
  "repository": {
    "type": "git",
    "url": "https://github.com/your-username/spreadsheet.git"
  },
  "keywords": [],
  "author": "",
  "license": "ISC",
  "type": "commonjs"
}
```

`npm init` asks questions about the project; `-y` answers "yes, use your guesses" to all of them. Some guesses are good (the name comes from the folder, the repository from your Git remote), and some are wrong for this project. You'll fix them in a moment.

The file is in **JSON** (JavaScript Object Notation): `{ }` around `"name": value` pairs. It looks like a Python dictionary, and it's the most common format programs use to store and exchange data. Its rules are strict: keys in double quotes, no comma after the last item, no comments.

```check
file package.json -- Run npm init -y
```

## Install Vite

```powershell
npm install --save-dev vite
```

```text
PS C:\Users\you\Documents\spreadsheet> npm install --save-dev vite

added 15 packages, and audited 16 packages in 5s

8 packages are looking for funding
  run `npm fund` for details

found 0 vulnerabilities
```

You asked for one package and got 15: Vite itself, and the packages Vite depends on. Three things appeared in your folder:

- **`node_modules/`**: a folder holding all 15 packages' code. It belongs to this project only. Another project gets its own `node_modules`, possibly with different versions, so projects can't break each other. (Python needs a *virtual environment* to get this; npm does it by default.)
- **`package-lock.json`**: the exact version of every one of the 15 packages that was installed. Anyone who installs from this file gets precisely the same versions, so "it works on my machine" means it works on theirs too.
- In **`package.json`**, a new section: `"devDependencies": { "vite": "^8.3.2" }`. Your number may be newer.

```predict
question: package.json will say `"vite": "^8.3.2"`. Without a lockfile, which versions could a fresh `npm install` choose?
choice: 8.9.0, but not 9.0.0
choice: The newest, even 9.0.0
choice: Only exactly 8.3.2
answer: 8.9.0, but not 9.0.0
explain: `^` accepts any later version with the same first number, the MAJOR one. By convention a new major version may break the code that uses it, so `^` never moves to one by itself. The lockfile then pins the exact version that was chosen, so every install after it gets the same one.
```

`--save-dev` records Vite as a **dev dependency**: something needed to *build* the project, not part of the finished app. `^8.3.2` is a version **range**: "8.3.2, or any later 8.x". Version numbers are `MAJOR.MINOR.PATCH`; a new MAJOR number means the package changed in ways that can break code using it, so `^` accepts newer minor and patch versions but never a new major one. That convention is called **semantic versioning**.

```check
dir node_modules/vite -- Run npm install --save-dev vite
file package-lock.json
contains package.json "\"vite\"" label="package.json lists vite"
```

## Keep node_modules out of Git

```powershell
git status
```

```text
Untracked files:
  (use "git add <file>..." to include in what will be committed)
        columns.js
        node_modules/
        package-lock.json
        package.json
```

(That's the end of the output; `columns.js` is listed only if you haven't committed it.)

`node_modules` must **not** be committed. It's large, it can always be recreated from `package.json` and `package-lock.json` with `npm install`, and parts of it are specific to your operating system. Add it to `.gitignore` (lesson 1.5):

```text file=.gitignore
.env
*.log
node_modules
```

Run `git status` again: `node_modules/` is gone from the list. `package.json` and `package-lock.json` stay: they **are** committed, because they're how anyone else gets the same packages.

```check
git-ignored node_modules -- Add the line node_modules to .gitignore.
git-ignored .env -- Keep .env in .gitignore too.
```

## Fix package.json

Edit `package.json` to this. Keep your own version number for `vite`.

```json file=package.json
{
  "name": "spreadsheet",
  "version": "0.1.0",
  "private": true,
  "type": "module",
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview"
  },
  "devDependencies": {
    "vite": "^8.3.2"
  }
}
```

- **`"version": "0.1.0"`**: the project's own version. Below 1.0 says "not finished yet".
- **`"private": true`**: this project is not a package for others; npm will refuse to publish it by accident.
- **`"type": "module"`**: JavaScript files here use `import` and `export`. npm's guess, `commonjs`, is an older module system from before JavaScript had its own.
- **`"scripts"`**: named commands. `npm run dev` runs `vite`, `npm run build` runs `vite build`. Scripts give every project the same command names, whatever tools it uses underneath.
- Removed: `main` (only for packages others import), `repository`, `keywords`, `author`, `license` and `description` (only used when publishing), and npm's placeholder `test` script (sprint 6 adds a real one).

Then list the scripts:

```powershell
npm run
```

```text
PS C:\Users\you\Documents\spreadsheet> npm run
Scripts available in spreadsheet@0.1.0 via `npm run`:
  dev
    vite
  build
    vite build
  preview
    vite preview
```

```check
contains package.json "\"type\": \"module\"" -- Set "type": "module"
contains package.json "\"dev\": \"vite\"" -- Add the scripts section.
run "npm run" stdout="vite build" label="`npm run` lists the dev, build and preview scripts"
```

## An experiment: throw node_modules away {#reinstall}

`node_modules` isn't committed, so anyone who clones the project gets it by running `npm install`. Prove that works by deleting yours. Predict first:

```predict
question: You delete `node_modules` and run `npm install`. Which version of Vite comes back?
choice: Exactly the same version as before
choice: The newest one npm can find
answer: Exactly the same version as before
explain: `npm install` follows `package-lock.json`, which records the exact version of every package, so a fresh install rebuilds the same folder. That's what makes "it works on my machine" true on every machine.
verify: node -e "console.log(require('./node_modules/vite/package.json').version === require('./package-lock.json').packages['node_modules/vite'].version ? 'Exactly the same version as before' : 'The newest one npm can find')"
```

```powershell
Remove-Item -Recurse -Force node_modules
npm install
```

`-Recurse -Force` deletes a folder and everything in it without asking: a command to type carefully. `npm install` reads the lockfile and puts back all 15 packages.

### What you just trusted

Installing a package runs other people's code on your computer: some packages run a script during the install itself, and every package runs inside your program. That's the **supply chain**: your project is only as safe as everything it installs, and everything *those* packages install. Three habits professionals keep:

- **Look before you install.** A package's page on npmjs.com shows who publishes it, how many people use it and when it last changed. Attackers publish packages with names one letter off from popular ones (`vitee`), hoping for a typo.
- **Commit the lockfile.** It records not just versions but a checksum of each package, so a changed package is noticed.
- **Run `npm audit`.** It checks every installed package against a public list of known security problems:

```powershell
npm audit
```

If it reports problems, read what they are before acting. `npm audit fix` updates packages within their allowed ranges; `npm audit fix --force` may jump to new major versions and break the project, so never run it without reading what it will change.

```check
dir node_modules/vite -- Run npm install to put node_modules back.
run "npm ls vite" stdout="vite@" label="npm sees Vite installed again"
```

## Commit

```powershell
git add package.json package-lock.json .gitignore
git commit -m "Install Vite with npm"
```

```check
git-tracked package.json
git-tracked package-lock.json
git-untracked node_modules/vite/package.json label="node_modules is not committed"
git-clean
```

## Your turn: a package of your own choosing to install

Make a second, tiny npm project inside the playground, and use a real package in it. In `playground/npm-lab`:

1. Make the folder, `cd` into it, and run `npm init -y`.
2. Install **picocolors** (version 1.1.1), a small library that prints coloured text in terminals, as an ordinary **dependency** (not a dev dependency: this program needs it to run, not just to be built). Look at its page on npmjs.com first, as a habit: who publishes it, how widely it's used.
3. Write `index.mjs` that imports it and prints `npm lab works` in green: `import pc from "picocolors";` then `console.log(pc.green("npm lab works"));`.
4. Run it with `node index.mjs`, go back up to the project folder, and commit.

`node_modules` inside the playground is already ignored: the `.gitignore` line `node_modules` matches a folder of that name anywhere in the project.

```check
run "node playground/npm-lab/index.mjs" stdout="npm lab works" label="the lab program runs and prints npm lab works"
run "node -e \"const p = require('./playground/npm-lab/package.json'); process.exit(p.dependencies && p.dependencies.picocolors ? 0 : 1)\"" label="picocolors is an ordinary dependency" -- Install it without --save-dev: npm install picocolors@1.1.1
file playground/npm-lab/package-lock.json -- The lockfile is made by npm install.
git-ignored playground/npm-lab/node_modules -- Keep the .gitignore line node_modules.
git-tracked playground/npm-lab/package-lock.json -- Commit the lab, lockfile included: git add playground, then git commit.
git-clean
```

The checks can't see whether you looked at the package's page first. That habit is yours to keep.
