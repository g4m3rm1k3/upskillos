### The story so far

Lesson 9.5 added comparisons: `=A1>100` is TRUE or FALSE, worked out after all the arithmetic, with Excel's rules for comparing text, numbers and booleans in `src/compare.ts`. So a formula can now ask a question. Nothing can act on the answer yet.

### What this lesson builds

`IF(test, then, otherwise)`: the test's answer chooses which of the other two is the cell's value.

```text
 =IF(B1=0, 0, 10/B1)        with B1 = 0

 test        B1=0      → TRUE
 then        0         → the value: 0
 otherwise   10/B1     → never worked out, so no #DIV/0!
```

That last line is the hard part. Today, `evaluate` works out every argument *before* calling a function, so `10/B1` would be worked out, and every cell of a range read, whether `IF` needs it or not. This lesson changes how functions receive their arguments: as **`Argument`s**, each worked out only when the function asks.

## Arguments are worked out first {#eager}

JavaScript does the same thing the spreadsheet does now. This step opens `playground/js/lazy.mjs`:

```javascript file=playground/js/lazy.mjs
function loud(name, value) {
  console.log("working out", name);
  return value;
}

function pick(test, yes, no) {
  return test ? yes : no;
}

function pickLater(test, yes, no) {
  return test ? yes() : no();
}

console.log(pick(true, loud("yes", 1), loud("no", 2)));
console.log(pickLater(true, () => loud("yes", 1), () => loud("no", 2)));
```

**The three functions, their inputs, and what they give back:**

| function | inputs | returns |
|---|---|---|
| `loud` | a name and a value | the value, after printing the name |
| `pick` | a test and two values | one of the values |
| `pickLater` | a test and two *functions* | what one of the functions gives, after calling only that one |

Before you run it, predict:

```predict
question: When `pick(true, loud("yes", 1), loud("no", 2))` runs, which `loud` calls happen?
choice: Only yes
choice: Both
answer: Both
explain: JavaScript works out every argument before the call starts, so both `loud`s run, and `pick` receives two plain numbers. This is called **eager** evaluation. `pick` can choose which to *return*, but it's too late to choose which to *work out*.
verify: node -e "let n = 0; const loud = (v) => { n++; return v; }; const pick = (t, a, b) => (t ? a : b); pick(true, loud(1), loud(2)); console.log(n === 2 ? 'Both' : 'Only yes')"
```

Run it: `node playground/js/lazy.mjs`.

```text
working out yes
working out no
1
working out yes
1
```

`pickLater` receives `() => loud("yes", 1)`: not a value, but a function that will work the value out when called. A function with no arguments, wrapped around work to delay it, is called a **thunk**. `pickLater` calls only the thunk it needs, so `no` is never worked out. Waiting until a value is needed is called **lazy** evaluation, and it's what `IF` needs.


## The tests {#tests}

The tests are supplied: click **Create provided src/if.test.ts** and read them:

```typescript file=src/if.test.ts provided
import { describe, expect, it } from "vitest";
import { evaluate } from "./evaluate.ts";
import { parse } from "./parser.ts";
import type { Value } from "./values.ts";

describe("IF", () => {
  it("chooses between two values", () => {
    expect(evaluate(parse('IF(12>10, "large", "small")'), () => "")).toBe("large");
    expect(evaluate(parse('IF(2>10, "large", "small")'), () => "")).toBe("small");
  });

  it("gives FALSE when there's no third argument and the test fails", () => {
    expect(evaluate(parse("IF(1>2, 5)"), () => "")).toBe(false);
  });

  it("avoids an error in the branch it doesn't take", () => {
    const b1IsZero = (): Value => 0;
    expect(evaluate(parse("IF(B1=0, 0, 10/B1)"), b1IsZero)).toBe(0);
  });

  it("only works out the branch it takes", () => {
    let cellsRead = 0;
    const counting = (): Value => {
      cellsRead++;
      return 1;
    };
    evaluate(parse("IF(1>0, 5, SUM(A1:A1000))"), counting);
    expect(cellsRead).toBe(0);
  });

  it("rejects a test that isn't TRUE, FALSE or a number", () => {
    expect(evaluate(parse('IF("yes", 1, 2)'), () => "")).toEqual({ error: "#VALUE!" });
  });
});
```

### What each test protects

| test | protects | the bug it would catch |
|---|---|---|
| chooses between two values | `IF` itself | the test's answer ignored, or the branches the wrong way round |
| gives FALSE when there's no third argument and the test fails | the optional third argument | `=IF(1>2, 5)` crashing on the missing argument, or showing 0 |
| avoids an error in the branch it doesn't take | laziness, as the user sees it | `=IF(B1=0, 0, 10/B1)` showing `#DIV/0!` when B1 is 0 |
| only works out the branch it takes | laziness, counted | `SUM(A1:A1000)` reading 1,000 cells for a branch nobody uses |
| rejects a test that isn't TRUE, FALSE or a number | the test's rules | `IF("yes", 1, 2)` treating any text as TRUE, as JavaScript's `if` would |

The fourth test counts `valueAt` calls: `counting` is a `valueAt` that adds 1 to `cellsRead` each time a cell is read. It passes only if no cell is read at all.

## An argument that waits {#argument}

An `Argument` is a pair of thunks: one for the argument's single value, one for every value it stands for. This step adds the type to `src/functions.ts`, next to the old one, without using it yet:

```typescript file=src/functions.ts
import type { ErrorValue, Value } from "./values.ts";

// One argument of a function call, not yet worked out: the function decides whether, and how.
export interface Argument {
  value(): Value;
  values(): Value[];
}

// A function receives its arguments' values: a list for each argument, holding every cell of a
// range, or the one value of anything else.
export type FormulaFunction = (args: Value[][]) => Value;

// The numbers among all the arguments' values, skipping text and empty cells, or the first error.
function numbers(args: Value[][]): number[] | ErrorValue {
  const found: number[] = [];
  for (const arg of args) {
    for (const value of arg) {
      if (typeof value === "object") {
        return value;
      }
      if (typeof value === "number") {
        found.push(value);
      }
    }
  }
  return found;
}

function sum(args: Value[][]): Value {
  const all = numbers(args);
  return Array.isArray(all) ? all.reduce((total, n) => total + n, 0) : all;
}

function average(args: Value[][]): Value {
  const all = numbers(args);
  if (!Array.isArray(all)) {
    return all;
  }
  return all.length === 0 ? { error: "#DIV/0!" } : all.reduce((total, n) => total + n, 0) / all.length;
}

function min(args: Value[][]): Value {
  const all = numbers(args);
  return Array.isArray(all) ? all.reduce((least, n) => Math.min(least, n), all[0] ?? 0) : all;
}

function max(args: Value[][]): Value {
  const all = numbers(args);
  return Array.isArray(all) ? all.reduce((most, n) => Math.max(most, n), all[0] ?? 0) : all;
}

function count(args: Value[][]): Value {
  let total = 0;
  for (const arg of args) {
    total += arg.filter((value) => typeof value === "number").length;
  }
  return total;
}

export const functions = new Map<string, FormulaFunction>([
  ["SUM", sum],
  ["AVERAGE", average],
  ["MIN", min],
  ["MAX", max],
  ["COUNT", count],
]);
```

| method | gives | for `A1:A3` | for `10/B1` |
|---|---|---|---|
| `value()` | the argument's one value | `#VALUE!`, as a range on its own always is | the division's result |
| `values()` | every value it stands for | the three cells' values | a list of one: the division's result |

`SUM` wants `values()`; `IF` wants `value()`, and only for the arguments it uses.

## Making the Arguments {#make}

`evaluate` now wraps each argument instead of working it out. This step replaces `valuesOf` with `argument` in `src/evaluate.ts`:

```typescript file=src/evaluate.ts
import { cellsIn, type Address } from "./address.ts";
import { compare } from "./compare.ts";
import type { Expression, Operator } from "./expression.ts";
import { functions, type Argument } from "./functions.ts";
import type { ErrorValue, Value } from "./values.ts";

export function evaluate(expression: Expression, valueAt: (address: Address) => Value): Value {
  switch (expression.kind) {
    case "number":
    case "text":
      return expression.value;
    case "cell":
      return valueAt(expression.address);
    case "range":
      return { error: "#VALUE!" };
    case "call": {
      const run = functions.get(expression.name);
      if (run === undefined) {
        return { error: "#NAME?" };
      }
      return run(expression.args.map((arg) => argument(arg, valueAt)));
    }
    case "negate": {
      const operand = toNumber(evaluate(expression.operand, valueAt));
      return typeof operand === "number" ? -operand : operand;
    }
    case "binary": {
      const left = toNumber(evaluate(expression.left, valueAt));
      if (typeof left !== "number") {
        return left;
      }
      const right = toNumber(evaluate(expression.right, valueAt));
      if (typeof right !== "number") {
        return right;
      }
      return calculate(expression.op, left, right);
    }
    case "compare": {
      const left = evaluate(expression.left, valueAt);
      if (typeof left === "object") {
        return left;
      }
      const right = evaluate(expression.right, valueAt);
      if (typeof right === "object") {
        return right;
      }
      return compare(expression.op, left, right);
    }
  }
}

// An argument is worked out only when the function asks for it.
function argument(expression: Expression, valueAt: (address: Address) => Value): Argument {
  return {
    value: () => evaluate(expression, valueAt),
    values: () =>
      expression.kind === "range"
        ? cellsIn(expression.from, expression.to).map(valueAt)
        : [evaluate(expression, valueAt)],
  };
}

function toNumber(value: Value): number | ErrorValue {
  if (typeof value === "number") {
    return value;
  }
  if (typeof value === "boolean") {
    return value ? 1 : 0;
  }
  if (typeof value === "string") {
    return value === "" ? 0 : { error: "#VALUE!" };
  }
  return value;
}

function calculate(op: Operator, left: number, right: number): Value {
  switch (op) {
    case "+":
      return left + right;
    case "-":
      return left - right;
    case "*":
      return left * right;
    case "/":
      return right === 0 ? { error: "#DIV/0!" } : left / right;
    case "^":
      return left ** right;
  }
}
```

**`argument`'s inputs, and what it gives back:**

| | what it is | example |
|---|---|---|
| input `expression` | one argument's tree | `10/B1` |
| input `valueAt` | how to read a cell | the workbook's |
| returns | an `Argument`: two thunks, nothing worked out yet | `{ value: () => …, values: () => … }` |

The thunks are **closures** (lesson 3.4): they keep `expression` and `valueAt` after `argument` returns, so whenever a function calls `value()`, perhaps never, the work happens then.

## IF's test {#is-true}

What counts as TRUE? Excel's rules: TRUE and FALSE mean themselves, a number is TRUE unless it's 0, an empty cell is FALSE, and other text is an error. JavaScript's `if` would treat `"yes"` as true, which hides mistakes. This step adds the rules as `isTrue`, in `src/functions.ts`:

```typescript file=src/functions.ts

  values(): Value[];

}

  }
  return total;

function isTrue(test: Value): boolean | ErrorValue {
  if (typeof test === "object") {
    return test;
  }
  if (typeof test === "string" && test !== "") {
    return { error: "#VALUE!" };
  }
  return test === true || (typeof test === "number" && test !== 0);

  ["AVERAGE", average],

```

**`isTrue`'s input, and what it gives back:**

| input `test` | returns |
|---|---|
| `true`, `false` | the same |
| a number | `true`, unless it's `0` |
| `""`, an empty cell | `false` |
| any other text | `{ error: "#VALUE!" }` |
| an error | the error, passed on |

The last line, `test === true || (typeof test === "number" && test !== 0)`, is `true` for TRUE and for numbers other than 0. Everything else that reaches it, FALSE, 0 and `""`, gives `false`.

## IF {#if}

`choose` checks it has two or three arguments, asks for the test's value, and then asks for exactly one more. This step adds it, and registers it as `IF`:

```typescript file=src/functions.ts
import type { ErrorValue, Value } from "./values.ts";

// One argument of a function call, not yet worked out: the function decides whether, and how.
export interface Argument {
  value(): Value;
  values(): Value[];
}

export type FormulaFunction = (args: Argument[]) => Value;

// The numbers among all the arguments' values, skipping text and empty cells, or the first error.
function numbers(args: Argument[]): number[] | ErrorValue {
  const found: number[] = [];
  for (const arg of args) {
    for (const value of arg.values()) {
      if (typeof value === "object") {
        return value;
      }
      if (typeof value === "number") {
        found.push(value);
      }
    }
  }
  return found;
}

function sum(args: Argument[]): Value {
  const all = numbers(args);
  return Array.isArray(all) ? all.reduce((total, n) => total + n, 0) : all;
}

function average(args: Argument[]): Value {
  const all = numbers(args);
  if (!Array.isArray(all)) {
    return all;
  }
  return all.length === 0 ? { error: "#DIV/0!" } : all.reduce((total, n) => total + n, 0) / all.length;
}

function min(args: Argument[]): Value {
  const all = numbers(args);
  return Array.isArray(all) ? all.reduce((least, n) => Math.min(least, n), all[0] ?? 0) : all;
}

function max(args: Argument[]): Value {
  const all = numbers(args);
  return Array.isArray(all) ? all.reduce((most, n) => Math.max(most, n), all[0] ?? 0) : all;
}

function count(args: Argument[]): Value {
  let total = 0;
  for (const arg of args) {
    total += arg.values().filter((value) => typeof value === "number").length;
  }
  return total;
}

// IF's test: TRUE, FALSE or a number, where 0 is FALSE. An empty cell is FALSE; other text is #VALUE!.
function isTrue(test: Value): boolean | ErrorValue {
  if (typeof test === "object") {
    return test;
  }
  if (typeof test === "string" && test !== "") {
    return { error: "#VALUE!" };
  }
  return test === true || (typeof test === "number" && test !== 0);
}

function choose(args: Argument[]): Value {
  const [condition, ifTrue, ifFalse] = args;
  if (condition === undefined || ifTrue === undefined || args.length > 3) {
    return { error: "#VALUE!" };
  }
  const test = isTrue(condition.value());
  if (typeof test === "object") {
    return test;
  }
  if (test) {
    return ifTrue.value();
  }
  return ifFalse === undefined ? false : ifFalse.value();
}

export const functions = new Map<string, FormulaFunction>([
  ["SUM", sum],
  ["AVERAGE", average],
  ["MIN", min],
  ["MAX", max],
  ["COUNT", count],
  ["IF", choose],
]);
```

**`choose`'s input, and what it gives back:**

| | what it is | example |
|---|---|---|
| input `args` | two or three `Argument`s | `B1=0`, `0`, `10/B1` |
| returns | the second argument's value if the test is TRUE, the third's if not, FALSE if there's no third | `0` |
| or returns | `#VALUE!` for the wrong number of arguments or a bad test; the test's error | `=IF(1)` |

- **`const [condition, ifTrue, ifFalse] = args;`** is destructuring (lesson 6.3): the first three arguments get names, and any missing one is `undefined`.
- **`ifTrue.value()`** is the only place the second argument is worked out, and only on this path.

The trace, for `=IF(B1=0, 0, 10/B1)` with B1 = 0:

| step | what happens | cells read |
|---|---|---|
| `condition.value()` | `B1=0` worked out: B1 is 0, so TRUE | B1 |
| `isTrue(true)` | `true` | |
| `ifTrue.value()` | `0` | |
| `ifFalse` | never called: `10/B1` is never worked out | |

## Your turn: work done once, in the playground

A thunk does its work every time it's called. In `playground/js/once.mjs`, write and export `once(work)`: it takes a thunk and gives back a new thunk that calls `work` the first time, and from then on gives back the same result without calling `work` again. It mustn't call `work` before the first call. Commit.

| code | gives |
|---|---|
| `const answer = once(() => { runs++; return 42; })` | a thunk; `runs` is still 0 |
| `answer()`, then `answer()` again | `42` both times; `runs` is 1 |
| `once(() => undefined)`, called twice | `work` ran once, even though its result was `undefined` |

```hints
nudge: The new thunk has to remember two things between calls: whether `work` has run, and what it gave. Lesson 3.4's closures can remember.
concept: Declare `let done = false;` and `let result;` inside `once`, then return an arrow function that, if not `done`, calls `work()`, stores the result, and sets `done`. Checking `result === undefined` instead of a `done` flag fails for work that really does give `undefined`: it would run every time.
shape: `export function once(work) { let done = false; let result; return () => { if (!done) { result = work(); done = true; } return result; }; }`
answer: ~~~javascript
export function once(work) {
  let done = false;
  let result;
  return () => {
    if (!done) {
      result = work();
      done = true;
    }
    return result;
  };
}
~~~
```
