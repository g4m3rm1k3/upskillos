Outcome: trace a visible style to its rule, then change a whole design using variables. A selector chooses elements; declarations inside braces set properties. The cascade resolves competing declarations using origin, specificity and order. A class selector is more specific than an element selector. Avoid escalating with !important.

### The story so far

You have meaningful HTML and a hypothesis about what matters most to visitors. Now you will turn that hierarchy into a visual hierarchy: heading scale, readable lines, consistent spacing and clearly recognizable links.

Keep the browser’s Elements and Computed panels nearby. CSS is easier to learn when each declaration has a visible effect that you can temporarily change and undo.

## Name the visual decisions

### Read a rule as a sentence

```css
section { padding: var(--space); }
```

Read this as “For each section, set its inside spacing to the value named --space.” `section` is the selector, `padding` the property, and `var(--space)` the value expression. The colon separates property from value; a semicolon separates declarations.

A **design token** is a reusable named decision. It is like labeling a paint tin “wall surface” instead of writing the exact mixture on every room plan. When the decision changes, you can replace the tin. The analogy has a limit: tokens participate in CSS inheritance and the cascade, so a nested component can intentionally redefine one.

### Work through a box before styling the whole page

Suppose a section has width 240px, padding 16px on each side and a 2px border on each side. With content-box sizing, its outer border width is `240 + 32 + 4 = 276px`. With border-box, the outer border width stays 240px and the content receives `240 - 32 - 4 = 204px`. Margin lies outside that border and is not included in either figure.

Predict which box fits a 250px-wide parent. Then use DevTools’ box-model diagram to check the same arithmetic.

Custom properties begin with --; var() reads them. :root is the html element. rem uses the root font size, ch approximates a character width, and clamp chooses a fluid value with limits. A box has content, padding, border and margin. border-box includes padding and border in its declared width. Logical properties such as margin-inline follow writing direction. Type the rules and use the Computed panel to find the resulting heading size.

```css file=cafe/styles.css
/* Tokens name design decisions so one change can update the whole site. */
:root {
  --surface: #ffffff;
  --ink: #172b24;
  --accent: #176341;
  --space: 1rem;
  --radius: 0.75rem;
  font-family: system-ui, sans-serif;
  color: var(--ink);
  background: var(--surface);
  line-height: 1.6;
}
* { box-sizing: border-box; }
body { margin: 0; }
header, main, footer { max-width: 68rem; margin-inline: auto; padding: var(--space); }
h1 { font-size: clamp(2rem, 5vw, 3.5rem); line-height: 1.1; max-width: 18ch; }
h2 { line-height: 1.25; }
p { max-width: 65ch; }
a { color: var(--accent); text-underline-offset: 0.2em; }
a:focus-visible, button:focus-visible, input:focus-visible { outline: 3px solid var(--accent); outline-offset: 4px; }
section { border: 1px solid currentColor; border-radius: var(--radius); padding: var(--space); margin-block: var(--space); }
```

### Why these particular rules exist

`body { margin: 0; }` removes the browser’s default outer body margin so spacing is intentional. It is not a universal command to remove all breathing room: the header/main/footer rules add it back consistently.

`max-width: 68rem` gives wide screens a readable content measure instead of stretching every line edge to edge. `margin-inline: auto` shares unused horizontal space around that bounded box. On narrow screens the box still shrinks to available space.

`clamp(2rem, 5vw, 3.5rem)` means “use 5% of viewport width, but no smaller than 2rem and no larger than 3.5rem.” At a root size of 16px and a 1000px viewport, the candidates are 32px, 50px and 56px, so the chosen font size is 50px. At 320px, the preferred 16px is below the minimum and the result is 32px.

Unitless `line-height: 1.6` multiplies each element’s font size. A 20px font receives a 32px line box. It scales more naturally than an inherited fixed pixel line height.

### A debugging order for the cascade

First check whether the selector matches. Then inspect whether the declaration is valid. Then ask whether another rule wins. Finally inspect inheritance and layout constraints. Adding !important before answering those questions can hide the cause and make the next change harder.

**Rule of thumb:** reuse a small spacing and type scale before introducing one-off values. Break the scale when content gives you a reason, not merely because a random number looked close in one screenshot. A token should represent a shared decision, not every number in the stylesheet.

## Diagnose, explain and review

Temporarily add section { padding: 0; } at the end. Its equal specificity and later position win. Inspect the crossed-out earlier declaration, then remove the experiment. Compare text at 200% zoom: avoid fixed-height text boxes. The token check does not establish a good spacing hierarchy.
