SQLite runs inside a process. PostgreSQL is a separate server accepting connections. Your SQL file is still text, but its execution now happens in a chosen database on that server.

## Know which database receives a command

Install PostgreSQL 18 from the [official platform installers](https://www.postgresql.org/download/), including psql, createdb, pg_dump and pg_restore. This course is authored against PostgreSQL 18 and its author tests use 18.4. Keep the supplied authentication controls; do not expose a practice server publicly. An installer may create a local service and an administrative account. Follow its platform instructions and verify `psql --version`.

A **cluster** is one server's collection of databases. A database contains schemas; a schema is a namespace of tables and other objects. A session is one connected client's interaction with that database. Roles control privileges. The practice administrative role will create a disposable database, not modify an existing application database.

Run `createdb issue_desk_course` using your installed local account. Configure PGDATABASE to issue_desk_course: in zsh/bash use `export PGDATABASE=issue_desk_course`; in PowerShell use `$env:PGDATABASE='issue_desk_course'`. If your installer requires a host or role, set PGHOST and PGUSER similarly to its local connection values. Let the tool prompt for a password; do not put passwords into lesson files or commit them.

Run `psql -X -c "SELECT current_database(), current_user;"` and confirm the database and role. -X ignores personal psql startup customizations, making the experiment reproducible. In an interactive psql session, `\conninfo` shows connection information and `\q` exits. SQL still ends in semicolons. A semicolon does not end a transaction.

## Make the dialect differences visible

Create pg-model.sql from model.sql, changing generated integer keys to `INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`. PostgreSQL does not give a plain INTEGER PRIMARY KEY SQLite's automatic-number behavior. BY DEFAULT allows our explicit fixture IDs; production imports need a deliberate identity policy. Restart tickets at 100 so later generated IDs cannot collide with the explicit sample IDs 1–4. Sequence allocation is not a gap-free receipt counter and is not undone like normal row changes.

TIMESTAMPTZ represents an instant and displays it in the session time zone. It does not retain the original named zone; store that separately if the product needs it. PostgreSQL enforces integer column types, unlike SQLite's ordinary type affinity. Parent references are enforced without a SQLite pragma. The schema below otherwise keeps the already-taught design and includes the events table from chapter 7.

```sql file=pg-model.sql
CREATE TABLE teams (
    team_id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name TEXT NOT NULL UNIQUE
);
CREATE TABLE projects (
    project_id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    team_id INTEGER NOT NULL REFERENCES teams(team_id),
    name TEXT NOT NULL,
    UNIQUE (team_id, name)
);
CREATE TABLE users (
    user_id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    email TEXT NOT NULL UNIQUE
);
CREATE TABLE memberships (
    team_id INTEGER NOT NULL REFERENCES teams(team_id),
    user_id INTEGER NOT NULL REFERENCES users(user_id),
    role TEXT NOT NULL CHECK (role IN ('viewer', 'editor')),
    PRIMARY KEY (team_id, user_id)
);
CREATE TABLE tickets (
    ticket_id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    project_id INTEGER NOT NULL REFERENCES projects(project_id),
    title TEXT NOT NULL CHECK (length(trim(title)) > 0),
    estimate_minutes INTEGER CHECK (estimate_minutes >= 0),
    assignee_id INTEGER REFERENCES users(user_id),
    status TEXT NOT NULL CHECK (status IN ('open','closed')),
    created_at TIMESTAMPTZ NOT NULL,
    version INTEGER NOT NULL DEFAULT 1 CHECK (version > 0)
);
CREATE TABLE ticket_events (
    event_id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    ticket_id INTEGER NOT NULL REFERENCES tickets(ticket_id),
    new_status TEXT NOT NULL CHECK(new_status IN ('open','closed'))
);
ALTER TABLE tickets ALTER COLUMN ticket_id RESTART WITH 100;
```

```check
run "psql -X -qAt -v ON_ERROR_STOP=1 -c \"BEGIN; CREATE SCHEMA course_probe; SET LOCAL search_path=course_probe;\" -f pg-model.sql -f sample.sql -c \"SELECT count(*)=4 FROM tickets;\" -c ROLLBACK" exit=0 label="Run against PostgreSQL in a rolled-back scratch schema" stdout="t" -- Run the command yourself and compare the actual result with the lesson trace.
```

## Use disposable probes

```predict
question: Does changing the PostgreSQL session time zone change the stored instant?
choice: No
choice: Yes
answer: No
explain: It changes the display of a timestamptz value, not the instant it represents.
```

The check starts BEGIN, creates a scratch schema named course_probe, and uses SET LOCAL search_path to resolve unqualified names there until the transaction ends. It loads your files and ROLLBACK removes the scratch objects. This is test isolation, not an application migration. ON_ERROR_STOP makes psql stop on errors; -qAt requests quiet, unaligned, headerless results. A `t` result means true.

Try `SET TIME ZONE 'UTC'; SELECT created_at FROM tickets;` and then another named zone inside a probe. Compare equivalent instants at different offsets. A report for a local day should convert the start and next-day start to instants; daylight-saving days need not be 24 elapsed hours.
