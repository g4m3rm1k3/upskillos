Download two bank statements, October's and November's, and they overlap: October's runs to the 14th of November, November's starts on the 1st. Import both into a budget, and the first fortnight of November is counted twice. The obvious fix is "throw away the duplicates", and it's wrong in a way that's easy to miss: on the 7th, two coffees were bought, separately, for the same price, from the same café, and they look identical. Throwing away duplicates throws one of them away. The difference between those two answers is the difference between a **set** and a **multiset**, and it decides whether your totals are right. This lesson works through sets, their operations and their laws, and builds three Kit tools on them: `uniq`, `diff`, and, in the task, a `union` that merges the two statements correctly.

Why Python: its `set` type and `collections.Counter` put sets and multisets, with their operators, directly in the language, so each idea can be tried in one line.

## What a set is

A **set** is a collection where the only question is whether something is in it. It has no order, and nothing is in it twice. In Python, `{...}` with values makes one, and `set(...)` makes one from a list.

```predict

choice: 3 True False

answer: 2 True True
explain: A set holds each value once, so {'a', 'b', 'a'} has two members: its cardinality, len, is 2. 'a' in … asks membership: True. And two sets are equal when they have the same members, whatever order they were written in, so {1, 2} == {2, 1} is True.

```

Run it to see:

```

```

(On Windows, `.venv/Scripts/python`.) It prints `2 True True`. Three words to keep: **membership** (`x in s`), **cardinality** (`len(s)`, the number of members), and **equality** (same members). Membership is fast in a set, however big, because Python stores members by their **hash**, a number worked out from the value, and looks in one place instead of checking every member. That's also why only values that can't change can be members (01-04-02): a list could change after its hash was taken, so

```
.venv/bin/python -c "print({['a']})"
```

ends in `TypeError: cannot use 'list' as a set element (unhashable type: 'list')`. A tuple, which can't change, can be a member.

## Operations and their laws

Four operations combine sets, and one compares them:

| Operation | Python | Members |
|---|---|---|
| **Union** A ∪ B | `a \| b` | In A or in B (or both) |
| **Intersection** A ∩ B | `a & b` | In both |
| **Difference** A − B | `a - b` | In A and not in B |
| **Symmetric difference** A △ B | `a ^ b` | In exactly one of them |
| **Subset** A ⊆ B | `a <= b` | True if every member of A is in B |

They are 01-02's logic, member by member: `x in a | b` is `x in a or x in b`, `&` is `and`, `-` is `and not`, `^` is XOR. So the laws of logic become laws of sets: union and intersection are commutative and associative, each distributes over the other, and De Morgan's laws hold with "not" as the difference from a **universe** U of everything under discussion: U − (A ∪ B) = (U − A) ∩ (U − B).

Laws you can't check are claims. These can be checked the way 01-02-02 checked equivalences, by trying every case. Create `laws.py`:

```python file=kit/laws.py
import itertools

# Check laws of set algebra on every subset of a small universe: with 3
# elements there are 8 subsets, so 512 ways to pick A, B and C.
U = {1, 2, 3}
SUBSETS = [set(c) for n in range(len(U) + 1) for c in itertools.combinations(sorted(U), n)]

LAWS = {
    "A | B == B | A": lambda a, b, c: a | b == b | a,
    "A & (B | C) == (A & B) | (A & C)": lambda a, b, c: a & (b | c) == (a & b) | (a & c),
    "U - (A | B) == (U - A) & (U - B)": lambda a, b, c: U - (a | b) == (U - a) & (U - b),
    "A | (A & B) == A": lambda a, b, c: a | (a & b) == a,
    "A - (B - C) == (A - B) - C": lambda a, b, c: a - (b - c) == (a - b) - c,
}

print(len(SUBSETS), "subsets,", len(SUBSETS) ** 3, "triples")
for name, law in LAWS.items():
    broken = [(a, b, c) for a in SUBSETS for b in SUBSETS for c in SUBSETS if not law(a, b, c)]
    if broken:
        a, b, c = broken[0]
        print(f"{name}: fails {len(broken)} times, first with A={a or '{}'} B={b or '{}'} C={c or '{}'}")
    else:
        print(f"{name}: holds")
```

`itertools.combinations(sorted(U), n)` gives every way to choose `n` of the members (01-02-02), so `SUBSETS` holds all 2³ = 8 subsets, from the empty set to U itself. Each law is a function of three sets, and the list comprehension tries all 8 × 8 × 8 = 512 triples. The last "law" is one people assume, because subtraction of numbers seems to work that way.

```predict
question: Does A - (B - C) == (A - B) - C hold for every triple of subsets?
choice: Yes, like the others
choice: No
answer: No
explain: Take A = {1}, C = {1}, B empty. On the left, B - C is empty, so A - (empty) is {1}. On the right, A - B is {1}, and {1} - C is empty. The left keeps what C protects; the right removes it. Difference isn't associative, just as 10 - (5 - 2) isn't (10 - 5) - 2.
```

## Products

One more way to make a set from two: the **Cartesian product** A × B, every pair with a first member from A and a second from B. Ledger's report grid (each person against each category) is one:


The size of a product is the product of the sizes: 2 × 3 = 6. That multiplication is why products matter in practice. A table of every row of one file paired with every row of another is a product, and two files of 10,000 rows make 100 million pairs. 02-03-02's join keeps only the pairs that match on a key, which is what stops that from happening.

## uniq: each one once

The first tool keeps each distinct row once, like the Unix `uniq` (which only removes repeats next to each other; this one removes them anywhere). Create `uniq.py`:

```python file=kit/uniq.py
import collections
import csv
import sys

from csvtool import parse_csv
from kitargs import fail, help_if_asked, take_flag

USAGE = "FILE [--count]"


# A CSV file's header, and its other records as tuples: unlike lists, tuples
# can be members of a set or keys of a dictionary.
def read_records(name):
    try:
        with open(name, encoding="utf-8", newline="") as file:
            rows = parse_csv(file.read())
    except OSError as error:
        fail(name + ": " + error.strerror)
    return rows[0], [tuple(row) for row in rows[1:]]


# Write records to standard output as CSV, each after an optional prefix.
def write(records, prefix=""):
    out = csv.writer(sys.stdout, lineterminator="\n")
    for record in records:
        sys.stdout.write(prefix)
        out.writerow(record)


# Each distinct record once, in the order it first appears: a set answers
# "seen it already?", and the list keeps the order a set doesn't have.
def distinct(records):
    seen = set()
    kept = []
    for record in records:
        if record not in seen:
            seen.add(record)
            kept.append(record)
    return kept


def main():
    help_if_asked(sys.argv[1:], USAGE)
    counting, args = take_flag(sys.argv[1:], "--count")
    if len(args) != 1:
        fail("expected one FILE; usage: " + USAGE)
    header, records = read_records(args[0])
    if counting:
        counts = collections.Counter(records)
        write([("count", *header)])
        write([(str(counts[record]), *record) for record in distinct(records)])
    else:
        write([header])
        write(distinct(records))


if __name__ == "__main__":
    main()
```

It reuses Kit's own pieces: `parse_csv` from 01-07-02, and `fail`, `help_if_asked` and `take_flag` from `kitargs`. Records become tuples so they can go in a set. `distinct` is a common pattern: a set for the question "have I seen this?" (fast) and a list for the order (which a set doesn't keep). `write` uses Python's `csv.writer`, so a field containing a comma is quoted on the way out; `lineterminator="\n"` stops it adding a `\r` of its own. `("count", *header)` is a tuple of `"count"` followed by everything in `header`.

A **multiset** (or bag) is a collection where things can appear more than once and the number of times matters. `collections.Counter` is Python's multiset: it maps each member to how many times it's there. A bank statement is a multiset of transactions. A list of subscribers' email addresses is a set: the same address twice is a mistake to remove. Which one your data is depends on the domain, not on the data's appearance, and it should be decided and written down, because a tool can't tell. (A real importer would look for a transaction id in the bank's export, a key that tells the two coffees apart, if the bank provides one. Many don't.)

## diff: what's missing

The second tool compares two files: what's only in the first, what's only in the second, and how much is in both. Since statements are multisets, it compares them as multisets: a transaction twice in one and once in the other is once extra. Create `diff.py`:

```python file=kit/diff.py
import collections
import sys

from kitargs import fail, help_if_asked
from uniq import read_records, write

USAGE = "FILE_A FILE_B"


# The records that are in one list more times than in the other, as
# multisets: a record twice in b and once in a is in b once more. The result
# keeps the order the records appear in.
def extra(records, other):
    left = collections.Counter(records) - collections.Counter(other)
    found = []
    for record in records:
        if left[record] > 0:
            left[record] -= 1
            found.append(record)
    return found


def main():
    help_if_asked(sys.argv[1:], USAGE)
    if len(sys.argv) != 3:
        fail("expected two files; usage: " + USAGE)
    header_a, a = read_records(sys.argv[1])
    header_b, b = read_records(sys.argv[2])
    if header_a != header_b:
        fail("the files have different columns: " + ",".join(header_a) + " and " + ",".join(header_b))
    only_a, only_b = extra(a, b), extra(b, a)
    write(only_a, "< ")
    write(only_b, "> ")
    both = sum((collections.Counter(a) & collections.Counter(b)).values())
    print(f"{len(only_a)} only in {sys.argv[1]}, {len(only_b)} only in {sys.argv[2]}, {both} in both")


if __name__ == "__main__":
    main()
```

Counters have the multiset operations: `-` subtracts counts (dropping any that reach zero or less), `&` keeps the smaller count of each, `|` the larger, and `+` adds them. `extra` subtracts, then walks the records in order, taking each extra one until its count runs out, so the output keeps the files' order. Two files with different columns aren't comparable, so `diff.py` says so instead of comparing them anyway. Save it and run it on the two statements:

## Tests for both

The tools get tests, as all of Kit's do (01-09). Create `tests/test_sets.py`:

```python file=kit/tests/test_sets.py
from diff import extra
from uniq import distinct

COFFEE = ("2026-11-07", "COFFEE CORNER", "-4.50")
RENT = ("2026-11-01", "RENT", "-950.00")


def test_distinct_keeps_the_first_of_each_in_order():
    assert distinct([RENT, COFFEE, RENT, COFFEE]) == [RENT, COFFEE]


def test_distinct_of_nothing_is_nothing():
    assert distinct([]) == []


def test_extra_counts_repeats():
    # Two coffees in one list and one in the other: one coffee is extra.
    assert extra([COFFEE, COFFEE, RENT], [COFFEE]) == [COFFEE, RENT]
    assert extra([COFFEE], [COFFEE, COFFEE, RENT]) == []


def test_extra_both_ways_add_up_to_the_difference_in_size():
    a, b = [COFFEE, COFFEE, RENT], [COFFEE, RENT, RENT, RENT]
    assert len(extra(a, b)) - len(extra(b, a)) == len(a) - len(b)
```

**What these checks establish, and what they don't.** They check that the laws hold on every case and the false one fails, that `uniq` collapses the coffees and `--count` shows them, that `diff` and `union` treat the statements as multisets, on the samples and on a second pair of files, and that the tools refuse mismatched files and are tested and committed. They can't check that you'd ask the domain question, "is a repeat here a mistake or a second real thing?", on data you haven't seen before. Every tool here is correct for one answer and wrong for the other, and the data alone never tells you which.

## What you can do now

- A **set** answers membership; it forgets **order** and **repetition**. Its size is its **cardinality**. Members must be **hashable** (tuples, not lists).
- **Union, intersection, difference, symmetric difference** and **subset** are logic's or, and, and-not, xor and implies, applied to each member; their **laws** can be checked on every case of a small universe, and false laws found the same way.
- The **Cartesian product** pairs every member with every member, and its size is the product of the sizes.
- A **multiset** counts repeats (`collections.Counter`: `+`, `-`, `&`, `|`). Whether data is a set or a multiset is a **domain** question; get it wrong and totals go wrong silently.
- "Merge without duplicates" means **multiset union** for transactions, and **set union** for a list of subscribers.
