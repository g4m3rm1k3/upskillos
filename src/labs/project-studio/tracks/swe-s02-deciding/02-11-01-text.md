How long is "héllo"? Kit's `count` has answered since 01-01-01: 7 bytes, 6 characters (with the newline). Now type the same word on a different keyboard, or paste it from a web page, and `count` may say 7 characters, because the é can be stored as one code point or as an e followed by a combining accent, and both look identical. A thumbs-up with a skin tone is two code points and eight bytes; a flag is two letters from a special alphabet; a family emoji can be seven code points joined together. Ask a person how many characters each has, and they say one. Text is where programs that are "obviously right" are wrong most often: lengths that don't match what's on the screen, searches that miss a word that's plainly there, sorting that puts "Zebra" before "apple", and, as this lesson finds in Kit, tools that work on one operating system and crash on another. This lesson takes text apart, teaches `count` to count the characters a person sees, and fixes the bug.

**By the end you can:**

- Tell bytes, UTF-8 and UTF-16 code units, code points and graphemes apart, and say which one a length should count.
- Count graphemes in a stream, a piece at a time.
- Normalize text before comparing it, and fold case properly.
- Explain why sorting text is a question about language, and why line endings and output encodings belong at the boundary.

**You need:** 01-01-01 and 01-01-04 (encodings, `count`'s machine and incremental decoder), 02-03-01 (`uniq.py`), 02-04-02 (boundaries). Commands run inside `kit`.

## Characters a person sees

Unicode defines where one grapheme ends and the next begins, in a standard called UAX #29, and its full rules are long. Python's standard library doesn't implement them (the third-party `regex` module does, as `\X`). A simplified version covers the common cases, as long as it's honest about what it doesn't. Create `graphemes.py`:

```python file=kit/graphemes.py
import unicodedata

# Counting the characters a person sees (graphemes), as a state machine fed a
# piece of text at a time, like count.py's. A simplified form of Unicode's
# rules (UAX #29): a code point joins the grapheme before it when it's
#   - a combining mark, a variation selector, a skin-tone modifier, or a
#     zero-width joiner (U+200D);
#   - anything straight after a zero-width joiner (an emoji sequence);
#   - the second of a pair of regional indicators (a flag);
#   - a line feed straight after a carriage return (CR LF is one).
# Not covered: Hangul syllables written as separate jamo, Indic conjuncts,
# and other rules of the full standard.
ZWJ = "‍"


def joins(previous, character, pair_open):
    if previous is None:
        return False
    if previous == "\r":
        return character == "\n"
    if previous == ZWJ:
        return True
    if is_regional(character):
        return pair_open
    return (
        unicodedata.category(character) in ("Mn", "Mc", "Me")
        or "︀" <= character <= "️"
        or "\U0001f3fb" <= character <= "\U0001f3ff"
        or character == ZWJ
    )


def is_regional(character):
    return "\U0001f1e6" <= character <= "\U0001f1ff"


def start():
    return {"previous": None, "pair_open": False, "count": 0}


# Count the graphemes that begin in this piece of text. pair_open says the
# last code point was a regional indicator still waiting for its partner.
def feed(state, text):
    previous, pair_open, count = state["previous"], state["pair_open"], state["count"]
    for character in text:
        joined = joins(previous, character, pair_open)
        if not joined:
            count += 1
        pair_open = is_regional(character) and not joined
        previous = character
    return {"previous": previous, "pair_open": pair_open, "count": count}


def count(text):
    return feed(start(), text)["count"]
```

It's a state machine fed a piece of text at a time, the same shape as `count`'s (01-01-04), because `count` reads its input in chunks and a grapheme can be split across two of them. It counts the code points that *start* a grapheme: every code point starts one unless `joins` says it belongs to the one before. `unicodedata.category` gives a code point's general category: `Mn`, `Mc` and `Me` are the combining marks. The state carries the previous code point (for CR LF and the joiner) and whether the last regional indicator is still waiting for its partner, so that four regional indicators make two flags, not one. The comment at the top says what it doesn't cover: a module that's a simplification should say so where its next reader will look.

```
.venv/bin/python -c "import graphemes; print(graphemes.count('héllo'), graphemes.count('\U0001f1ec\U0001f1e7\U0001f1eb\U0001f1f7'), graphemes.count('\U0001f469‍\U0001f4bb'))"
```

It prints `5 2 1`: five letters, two flags, one woman at a laptop.

## count, in graphemes

Now `count` counts them. Replace `count.py` with:

```python file=kit/count.py
import codecs
import json
import logging
import os
import sys

import graphemes
from kitargs import fail, help_if_asked, open_input, setup_logging, take_flag

log = logging.getLogger("count")

USAGE = "[FILE|-] [ENCODING] [--json]"

# ASCII whitespace, the six bytes from the definition of a word.
WHITESPACE = b" \t\n\r\x0b\x0c"
NEWLINE = 10  # the value of the byte b"\n"
CHUNK_SIZE = 65536  # how many bytes to read at a time (64 KiB)


# The counting as a state machine, fed one piece at a time.
def start(encoding):
    return {
        "bytes": 0,
        "newlines": 0,
        "words": 0,
        "in_word": False,
        "last": None,
        "line_length": 0,
        "longest": 0,
        "characters": 0,
        "decoder": codecs.getincrementaldecoder(encoding)(),
        "graphemes": graphemes.start(),
    }


def feed(state, chunk):
    in_word = state["in_word"]
    # bytes.split() splits on the same six whitespace bytes, and runs in C:
    # much faster than a Python loop over every byte. A word starts at a byte
    # that isn't whitespace, after one that is.
    words = state["words"] + len(chunk.split())
    # A word that crosses from the last chunk into this one was counted
    # there already: its second half is this chunk's first part.
    if in_word and chunk and chunk[0] not in WHITESPACE:
        words -= 1
    if chunk:
        in_word = chunk[-1] not in WHITESPACE
    line_length = state["line_length"]
    longest = state["longest"]
    for byte in chunk:
        if byte == NEWLINE:
            longest = max(longest, line_length)
            line_length = 0
        else:
            line_length += 1
    last = state["last"]
    if chunk:
        last = chunk[-1]
    characters = state["characters"]
    decoder = state["decoder"]
    seen = state["graphemes"]
    if decoder is not None:
        try:
            text = decoder.decode(chunk)
            characters += len(text)
            seen = graphemes.feed(seen, text)
        except UnicodeDecodeError:
            characters = None
            decoder = None
            seen = None
    return {
        "bytes": state["bytes"] + len(chunk),
        "newlines": state["newlines"] + chunk.count(b"\n"),
        "words": words,
        "in_word": in_word,
        "last": last,
        "line_length": line_length,
        "longest": longest,
        "characters": characters,
        "decoder": decoder,
        "graphemes": seen,
    }


def finish(state):
    lines = state["newlines"]
    if state["last"] is not None and state["last"] != NEWLINE:
        lines += 1
    characters = state["characters"]
    seen = state["graphemes"]
    if state["decoder"] is not None:
        try:
            text = state["decoder"].decode(b"", final=True)
            characters += len(text)
            seen = graphemes.feed(seen, text)
        except UnicodeDecodeError:
            characters = None
            seen = None
    return {
        "bytes": state["bytes"],
        "lines": lines,
        "words": state["words"],
        "characters": characters,
        "graphemes": None if seen is None else seen["count"],
        "longest": max(state["longest"], state["line_length"]),
    }


# The counting as a function: all the bytes in, counts out.
def measure(data, encoding):
    return finish(feed(start(encoding), data))


# Read a stream a piece at a time, feeding each piece to the machine.
def count_stream(stream, encoding):
    state = start(encoding)
    while True:
        chunk = stream.read(CHUNK_SIZE)
        if not chunk:
            break
        log.debug("read %d bytes", len(chunk))
        state = feed(state, chunk)
    return finish(state)


# The program: read the input, count it, print the result.
def main():
    setup_logging()
    help_if_asked(sys.argv[1:], USAGE)
    as_json, args = take_flag(sys.argv[1:], "--json")

    if len(args) > 1:
        encoding = args[1]
    else:
        encoding = "utf-8"

    name = None
    if len(args) > 0:
        name = args[0]

    # Check what can be checked before reading anything, and say what's wrong
    # in the user's terms. Anything else that goes wrong is a bug: let it crash.
    try:
        codecs.lookup(encoding)
    except LookupError:
        fail("unknown encoding: " + encoding)
    if name is not None and name != "-" and os.path.isdir(name):
        fail(name + ": is a folder, not a file")
    try:
        with open_input(name) as stream:
            counts = count_stream(stream, encoding)
    except OSError as error:
        fail(name + ": " + error.strerror)

    if as_json:
        print(json.dumps(counts))
        return
    print("bytes:", counts["bytes"])
    print("lines:", counts["lines"])
    print("words:", counts["words"])
    if counts["characters"] is None:
        print("characters: not", encoding, "text")
    else:
        print("characters:", counts["characters"])
        print("graphemes:", counts["graphemes"])
    print("longest:", counts["longest"])


if __name__ == "__main__":
    main()
```

Three small changes to the machine, all where the characters are already counted. `start` holds a grapheme state. `feed` keeps the text the decoder returns, counts its code points as before, and feeds the same text to `graphemes`. `finish` feeds the decoder's last piece, and reports `graphemes`, or `None` when the bytes weren't text in the encoding (the same rule as `characters`). The output gains a `graphemes:` line. Save it and run it:

```
.venv/bin/python count.py samples/hello.txt
```

`characters: 6` and `graphemes: 6`: for this file the two agree. They differ for decomposed accents and emoji.

import pytest

import graphemes
from count import feed, finish, measure, start

# Graphemes, the characters a person sees. Each example is counted from its
# UTF-8 bytes, whole and in pieces of every size: a grapheme, and even one
# code point, can be split between two pieces.
EXAMPLES = [
    ("", 0),
    ("héllo\n", 6),
    ("héllo\n", 6),
    ("\U0001f44d\U0001f3fd", 1),
    ("\U0001f1ec\U0001f1e7\U0001f1eb\U0001f1f7", 2),
    ("\U0001f469‍\U0001f4bb", 1),
    ("❤️", 1),
    ("a\r\nb\r\n", 4),
    ("\U0001f1ec", 1),
]


@pytest.mark.parametrize(("text", "expected"), EXAMPLES)
def test_count_counts_graphemes_in_pieces_of_every_size(text, expected):
    data = text.encode("utf-8")
    assert measure(data, "utf-8")["graphemes"] == expected
    for size in [1, 2, 3, 4096]:
        state = start("utf-8")
        for i in range(0, len(data), size):
            state = feed(state, data[i : i + size])
        assert finish(state)["graphemes"] == expected, f"in pieces of {size}"


def test_bytes_that_arent_utf8_have_no_grapheme_count():
    assert measure(b"h\xe9llo", "utf-8")["graphemes"] is None


# A known gap, written down as a test: a Hangul syllable spelled as three
# jamo is one character to a reader, and three here. If graphemes.py learns
# the Hangul rules, this test fails, and should then expect 1.
def test_a_hangul_syllable_spelled_as_jamo_is_not_joined_yet():
    assert graphemes.count("한") == 3

The fix belongs where text becomes bytes: say which encoding, instead of accepting the platform's. Replace `uniq.py` with:

```python file=kit/uniq.py
import collections
import csv
import sys

from csvtool import parse_csv
from kitargs import fail, help_if_asked, take_flag

USAGE = "FILE [--count]"


# A CSV file's header, and its other records as tuples: unlike lists, tuples
# can be members of a set or keys of a dictionary.
def read_records(name):
    try:
        with open(name, encoding="utf-8", newline="") as file:
            rows = parse_csv(file.read())
    except OSError as error:
        fail(name + ": " + error.strerror)
    return rows[0], [tuple(row) for row in rows[1:]]


# Write records to standard output as CSV, each after an optional prefix.
# Standard output is set to UTF-8 first: on Windows a pipe's default is the
# system's code page (cp1252 here), which writes É as a byte UTF-8 readers
# can't read, and can't write a combining accent at all.
def write(records, prefix=""):
    sys.stdout.reconfigure(encoding="utf-8")
    out = csv.writer(sys.stdout, lineterminator="\n")
    for record in records:
        sys.stdout.write(prefix)
        out.writerow(record)


# Each distinct record once, in the order it first appears: a set answers
# "seen it already?", and the list keeps the order a set doesn't have.
def distinct(records):
    seen = set()
    kept = []
    for record in records:
        if record not in seen:
            seen.add(record)
            kept.append(record)
    return kept


def main():
    help_if_asked(sys.argv[1:], USAGE)
    counting, args = take_flag(sys.argv[1:], "--count")
    if len(args) != 1:
        fail("expected one FILE; usage: " + USAGE)
    header, records = read_records(args[0])
    if counting:
        counts = collections.Counter(records)
        write([("count", *header)])
        write([(str(counts[record]), *record) for record in distinct(records)])
    else:
        write([header])
        write(distinct(records))


if __name__ == "__main__":
    main()
```

One line, with a comment that says why: `sys.stdout.reconfigure(encoding="utf-8")` makes standard output UTF-8 before anything is written. `diff.py`, `union.py` and `join.py` all write through this function, so all four tools are fixed. Run the same command again:

## Normal forms, case and order

`names.csv` holds one café three ways, and `uniq.py` sees three different records. Three more ideas decide whether two pieces of text are "the same":

- **Normalization.** Unicode's normal forms turn equivalent spellings into one. **NFC** composes (e + accent becomes é) and is the usual form for storing and comparing text; **NFD** decomposes; **NFKC** and **NFKD** also fold "compatibility" characters, such as the ligature ﬁ into f and i, or a superscript ² into 2, which is right for search and wrong for keeping what someone wrote. Normalize at the boundary, as text comes in, and comparisons inside the program can be plain `==`.
- **Case.** `lower()` isn't enough: German ß has no single-letter capital, so `"Straße".upper()` is `"STRASSE"`, and `"Straße".lower() == "strasse"` is false. **Case folding**, `"Straße".casefold()`, gives `"strasse"`, the form meant for case-insensitive comparison. And case rules depend on language: in Turkish, the capital of i is İ, with a dot.
- **Order.** Python's `sorted` orders by code point: `sorted(["b", "a", "Z", "é", "e"])` is `['Z', 'a', 'b', 'e', 'é']`, capitals before small letters and accented letters after z. People expect alphabetical order, and alphabetical order is a question about language: Swedish puts ä after z, German files it with a. That's **collation**, done properly with a collation library (ICU) or the system's locale (`locale.strxfrm`), and approximated with `key=str.casefold` for a simple case-insensitive list.

**Line endings** are one more boundary: a file may end its lines with LF (`\n`, macOS and Linux), CRLF (`\r\n`, Windows and RFC 4180's CSV) or, rarely now, CR alone. `count` counts LFs, so CRLF files count correctly; `graphemes.py` treats CR LF as one grapheme, as Unicode does; and Git can convert line endings on the way in and out (01-08-01's `.gitattributes`). The rule for all four: decide at the boundary, write it down, and test with text that isn't ASCII.

**What else, and why not.** You could install the `regex` module and count with `\X`, the full UAX #29 rules: more correct than `graphemes.py` (it handles the jamo), at the cost of a dependency to pin and keep up to date (01-06-05); for a tool where exact counts matter, it's the better choice. You could count code points and call them characters, as most software does: it's what `len` gives, and it's wrong for exactly the text people find most natural to type.
