# Lesson 25: ShaderMaterial Deep Dive — Noise, Procedural Patterns, RawShaderMaterial

**What you will build**
You will build a WebGL scene showcasing custom procedural textures, replacing image files with pure mathematical patterns. We will explore value noise, fractal brownian motion, and geometry-based patterns. The transferable insight here is that procedural textures generate patterns mathematically in the fragment shader with zero texture memory. Noise functions (like value noise or simplex noise approximations) produce organic, non-repetitive patterns. RawShaderMaterial strips Three.js's automatic uniform injections — you manage everything yourself, giving full control.

**What you need to know first**
- Lesson 24 (ShaderMaterial basics, uniforms, and varyings)

**Terms used in this lesson**
- **Procedural texture** — A pattern generated by a mathematical algorithm rather than being read from a stored image file. It allows infinite resolution and uses no texture memory.
- **Value noise** — A type of noise that works by generating pseudo-random values at discrete grid points and interpolating smoothly between them. It provides organic, continuous randomness.
- **FBM (Fractal Brownian Motion)** — A technique of adding multiple layers (octaves) of noise together at increasing frequencies and decreasing amplitudes. It creates natural-looking detail, like clouds or terrain.
- **Octave** — A single layer of noise in an FBM calculation. Higher octaves add finer, smaller details.
- **Pseudo-random** — A sequence of numbers that appears statistically random but is generated by a deterministic mathematical formula, ensuring the same input always yields the same output.
- **Bilinear interpolation** — A method of interpolating values across a 2D grid by interpolating linearly in one direction, and then in the other.
- **uv coordinates** — The 2D coordinates (ranging from 0.0 to 1.0) used to map textures or patterns onto the surface of a 3D geometry.
- **gl_FragColor** — The built-in GLSL variable in a fragment shader that determines the final RGBA color output for a pixel.

**Objects and methods used**

**THREE.ShaderMaterial**
- *What it is:* A material rendered with custom shaders.
- *Implementation:* `new THREE.ShaderMaterial(parameters)`
- *Its use:* Used to define the visual appearance using custom GLSL code for vertex and fragment shaders.
- *Type:* Class
- *Responsibility:* Manages the compilation and execution of custom shader code and the binding of uniforms and attributes.
- *Depends on:* GLSL shader strings, uniform definitions.
- *Connects to:* The WebGLRenderer, which compiles and runs the shaders.
- *Shape:* A core Three.js material subclass used for advanced rendering techniques.

**THREE.RawShaderMaterial**
- *What it is:* A lower-level shader material that does not automatically include Three.js built-in uniforms and attributes.
- *Implementation:* `new THREE.RawShaderMaterial(parameters)`
- *Its use:* Used when total control over the shader is required, avoiding the overhead of hidden Three.js injections.
- *Type:* Class
- *Responsibility:* Passes raw GLSL code directly to WebGL without appending standard Three.js shader chunks.
- *Depends on:* Complete, self-sufficient GLSL shader strings, manual definition of matrices and attributes.
- *Connects to:* The WebGLRenderer.
- *Shape:* A specialized Three.js material subclass for maximum performance and explicit control.

**THREE.TextureLoader**
- *What it is:* A utility for loading image files as textures.
- *Implementation:* `new THREE.TextureLoader().loadAsync(url)`
- *Its use:* Used to fetch an external image to be used within a custom shader.
- *Type:* Class
- *Responsibility:* Handles the asynchronous downloading and decoding of image data into a WebGL-compatible texture format.
- *Depends on:* A valid URL or path to an image file.
- *Connects to:* The network for downloading; outputs a `THREE.Texture` object.
- *Shape:* An asynchronous loader class provided by Three.js.

## Concept Unit: Value noise in GLSL — pseudo-random patterns

### The Problem
When trying to create organic surfaces like dirt, clouds, or skin, pure mathematical shapes like sine waves or checkers look too artificial. We need randomness, but true randomness (static) looks like TV snow. We need a way to generate smooth, continuous random values across a surface. How do we create mathematical randomness that connects smoothly?

### Introduce the concept in isolation
We will use a throwaway example to generate basic value noise on a plane.

```html
<!DOCTYPE html>
<html>
<head>
    <title>Value Noise Isolation</title>
</head>
<body>
    <script type="module">
        import * as THREE from 'https://unpkg.com/three@0.150.1/build/three.module.js';
        const renderer = new THREE.WebGLRenderer();
        renderer.setSize(window.innerWidth, window.innerHeight);
        document.body.appendChild(renderer.domElement);
        const camera = new THREE.OrthographicCamera(-1, 1, 1, -1, 0, 1);
        const scene = new THREE.Scene();
        
        const material = new THREE.ShaderMaterial({
            uniforms: { uTime: { value: 0 } },
            vertexShader: `varying vec2 vUv; void main(){vUv=uv;gl_Position=projectionMatrix*modelViewMatrix*vec4(position,1.0);}`,
            fragmentShader: `
                uniform float uTime;
                varying vec2 vUv;
                // Hash function: pseudo-random float from vec2
                float hash(vec2 p) {
                    return fract(sin(dot(p, vec2(127.1, 311.7))) * 43758.5453);
                }
                // Value noise: interpolated random values on a grid
                float noise(vec2 p) {
                    vec2 i = floor(p);
                    vec2 f = fract(p);
                    vec2 u = f * f * (3.0 - 2.0 * f);  // smoothstep
                    return mix(mix(hash(i), hash(i+vec2(1.0,0.0)), u.x),
                               mix(hash(i+vec2(0.0,1.0)), hash(i+vec2(1.0,1.0)), u.x), u.y);
                }
                void main() {
                    float n = noise(vUv * 8.0 + uTime * 0.3);
                    gl_FragColor = vec4(n, n, n, 1.0);  // greyscale noise
                }
            `,
        });
        const plane = new THREE.Mesh(new THREE.PlaneGeometry(2, 2), material);
        scene.add(plane);
        
        function animate(time) {
            material.uniforms.uTime.value = time * 0.001;
            renderer.render(scene, camera);
            requestAnimationFrame(animate);
        }
        animate(0);
    </script>
</body>
</html>
```

This generates a grayscale, cloudy pattern that slowly drifts. The `hash` function generates a pseudo-random number based on a grid coordinate. The `noise` function smooths out the transitions between these grid points using bilinear interpolation.

### Mechanical walkthrough
- `const material = new THREE.ShaderMaterial(...)`: Creates a material with custom GLSL.
- `uniforms: { uTime: { value: 0 } }`: Defines a time uniform passed from JavaScript to the shader.
- `varying vec2 vUv;`: Declares a varying to pass UV coordinates from the vertex shader to the fragment shader.
- `void main(){vUv=uv;...}`: Assigns the built-in `uv` attribute to our varying.
- `float hash(vec2 p)`: A function that takes a 2D coordinate and returns a pseudo-random float.
- `dot(p, vec2(127.1, 311.7))`: Takes the dot product of the input coordinate and a seemingly arbitrary vector. This scrambles the input.
- `sin(...) * 43758.5453`: Takes the sine of the scrambled value and multiplies it by a large number.
- `fract(...)`: Returns the fractional part (the decimal portion) of the result, ensuring the final hash is between 0.0 and 1.0. If `hash(vec2(0.3,0.5))` is called, `dot` produces `193.98`. The sine of this times `43758.5453` yields a large number, and `fract` extracts a random-looking decimal.
- `vec2 i = floor(p);`: Gets the integer grid cell coordinate.
- `vec2 f = fract(p);`: Gets the fractional position within the cell.
- `vec2 u = f * f * (3.0 - 2.0 * f);`: Calculates a smoothstep curve for interpolation.
- `mix(...)`: Performs linear interpolation. The nested `mix` calls perform bilinear interpolation between the four corners of the grid cell.
- `float n = noise(vUv * 8.0 + uTime * 0.3);`: Samples the noise function at scaled and animated UV coordinates.
- `gl_FragColor = vec4(n, n, n, 1.0);`: Outputs the noise value as grayscale RGB colors.

### CS lens
Value noise demonstrates pseudo-random number generation via mathematical hashing. Because GLSL lacks built-in random functions, we exploit the unpredictable nature of high-frequency sine waves multiplied by large constants to simulate randomness. Interpolating between discrete random grid points provides continuous C1 (first derivative) smoothness, essential for natural-looking procedural generation.

### SE lens
Packaging the noise and hash calculations into modular GLSL functions (`float hash(vec2 p)`, `float noise(vec2 p)`) makes the shader readable and reusable. It abstracts away the complex math, allowing the `main` function to succinctly describe the visual intent rather than the mathematical implementation.

## Concept Unit: FBM (Fractal Brownian Motion) — layered octaves

### The Problem
Value noise is smooth but lacks detail; it looks like a blurry blob. Natural textures like clouds or rocks have large structural shapes combined with tiny, sharp details. How do we add varying scales of detail to our smooth noise?

### Introduce the concept in isolation
We will modify our previous throwaway to implement Fractal Brownian Motion.

```html
<!DOCTYPE html>
<html>
<head><title>FBM Isolation</title></head>
<body>
    <script type="module">
        import * as THREE from 'https://unpkg.com/three@0.150.1/build/three.module.js';
        const renderer = new THREE.WebGLRenderer();
        renderer.setSize(window.innerWidth, window.innerHeight);
        document.body.appendChild(renderer.domElement);
        const camera = new THREE.OrthographicCamera(-1, 1, 1, -1, 0, 1);
        const scene = new THREE.Scene();
        
        const material = new THREE.ShaderMaterial({
            uniforms: { uTime: { value: 0 } },
            vertexShader: `varying vec2 vUv; void main(){vUv=uv;gl_Position=projectionMatrix*modelViewMatrix*vec4(position,1.0);}`,
            fragmentShader: `
                uniform float uTime;
                varying vec2 vUv;
                float hash(vec2 p) { return fract(sin(dot(p,vec2(127.1,311.7)))*43758.5453); }
                float noise(vec2 p) {
                    vec2 i=floor(p); vec2 f=fract(p);
                    vec2 u=f*f*(3.0-2.0*f);
                    return mix(mix(hash(i),hash(i+vec2(1.0,0.0)),u.x),
                               mix(hash(i+vec2(0.0,1.0)),hash(i+vec2(1.0,1.0)),u.x),u.y);
                }
                // FBM: sum noise at increasing frequencies, decreasing amplitude
                float fbm(vec2 p) {
                    float v = 0.0, a = 0.5;
                    for (int i = 0; i < 6; i++) {
                        v += a * noise(p);
                        p *= 2.0;    // double frequency each octave
                        a *= 0.5;    // half amplitude each octave
                    }
                    return v;  // result in [0,1]
                }
                void main() {
                    float f = fbm(vUv * 4.0 + uTime * 0.1);
                    gl_FragColor = vec4(f*0.2, f*0.5, f, 1.0);  // blue cloud-like
                }
            `,
        });
        const plane = new THREE.Mesh(new THREE.PlaneGeometry(2, 2), material);
        scene.add(plane);
        
        function animate(time) {
            material.uniforms.uTime.value = time * 0.001;
            renderer.render(scene, camera);
            requestAnimationFrame(animate);
        }
        animate(0);
    </script>
</body>
</html>
```

This generates a highly detailed, natural-looking blue cloud texture.

### Mechanical walkthrough
- `float fbm(vec2 p)`: Declares a function for Fractal Brownian Motion taking a 2D coordinate.
- `float v = 0.0, a = 0.5;`: Initializes the total value `v` to 0 and the starting amplitude `a` to 0.5.
- `for (int i = 0; i < 6; i++)`: A loop that runs 6 times, calculating 6 "octaves" of noise.
- `v += a * noise(p);`: Samples the noise function at point `p`, scales it by the current amplitude `a`, and adds it to the total value `v`.
- `p *= 2.0;`: Multiplies the coordinate by 2. This doubles the frequency of the noise for the next iteration, making the pattern smaller and more detailed.
- `a *= 0.5;`: Multiplies the amplitude by 0.5. This halves the influence of the higher-frequency noise, ensuring fine details don't overpower the broad shapes.
- `return v;`: Returns the accumulated sum. Tracing an example: `fbm` at `(0.5,0.5)`. Octave 0 adds `0.5*noise(0.5,0.5)`. Octave 1 evaluates at `p=(1,1)` and adds `0.25*noise(1,1)`. Octave 2 evaluates at `p=(2,2)` and adds `0.125*noise(2,2)`. The sum approaches a maximum of `~1.0`.
- `float f = fbm(vUv * 4.0 + uTime * 0.1);`: Samples the FBM function using scaled UVs and time.
- `gl_FragColor = vec4(f*0.2, f*0.5, f, 1.0);`: Maps the resulting scalar value to a blue color scale (less red, medium green, full blue).

### CS lens
FBM is an application of fractal geometry. By recursively accumulating self-similar patterns at exponentially scaling frequencies (lacunarity) and decaying amplitudes (gain or persistence), we synthesize textures that mimic the multi-scale structures found in nature (coastlines, clouds, mountains).

### SE lens
Using loops for repetitive shader calculations (like octaves) keeps the GLSL code compact. However, in WebGL 1.0, loop limits must be constant expressions (like `i < 6`). The tradeoff is that increasing the octave count dramatically increases the number of mathematical operations per pixel, which can become a performance bottleneck on lower-end GPUs.

## Concept Unit: Procedural patterns: checkerboard, stripes, circles

### The Problem
Not all textures are chaotic. How do we generate crisp, resolution-independent geometric patterns like stripes, circles, or checkerboards without relying on image files?

### Introduce the concept in isolation
We will test geometric distance and modulo functions in a throwaway shader.

```html
<!DOCTYPE html>
<html>
<head><title>Geometric Patterns Isolation</title></head>
<body>
    <script type="module">
        import * as THREE from 'https://unpkg.com/three@0.150.1/build/three.module.js';
        const renderer = new THREE.WebGLRenderer();
        renderer.setSize(window.innerWidth, window.innerHeight);
        document.body.appendChild(renderer.domElement);
        const camera = new THREE.OrthographicCamera(-1, 1, 1, -1, 0, 1);
        const scene = new THREE.Scene();
        
        const material = new THREE.ShaderMaterial({
            uniforms: { uTime: { value: 0 } },
            vertexShader: `varying vec2 vUv; void main(){vUv=uv;gl_Position=projectionMatrix*modelViewMatrix*vec4(position,1.0);}`,
            fragmentShader: `
                varying vec2 vUv;
                uniform float uTime;
                float checker(vec2 uv, float scale) {
                    vec2 p = floor(uv * scale);
                    return mod(p.x + p.y, 2.0);
                }
                float circles(vec2 uv, float scale, float thickness) {
                    float d = length(fract(uv*scale) - 0.5); 
                    return step(d, thickness);
                }
                float stripes(vec2 uv, float freq, float t) {
                    return step(0.5, fract(uv.x * freq + t));
                }
                void main() {
                    float c = checker(vUv, 8.0);
                    float circ = circles(vUv, 5.0, 0.3);
                    float stripe = stripes(vUv, 10.0, uTime * 0.5);
                    vec3 col = mix(vec3(0.1), vec3(1.0), c * circ + stripe * 0.3);
                    gl_FragColor = vec4(col, 1.0);
                }
            `,
        });
        const plane = new THREE.Mesh(new THREE.PlaneGeometry(2, 2), material);
        scene.add(plane);
        
        function animate(time) {
            material.uniforms.uTime.value = time * 0.001;
            renderer.render(scene, camera);
            requestAnimationFrame(animate);
        }
        animate(0);
    </script>
</body>
</html>
```

This generates an abstract composite of an animated striped background overlaid with circular cutouts of a checkerboard.

### Mechanical walkthrough
- `float checker(vec2 uv, float scale)`: Defines a function for a checkerboard.
- `vec2 p = floor(uv * scale);`: Scales the UVs and truncates to integers, creating discrete coordinate blocks. For `vUv=(0.1,0.2)` and `scale=8`, `floor((0.8,1.6))` yields `(0,1)`.
- `return mod(p.x + p.y, 2.0);`: Adds the row and column indices. If the sum is even, `mod 2` is `0.0`. If odd, `1.0`. `0+1` is `1`, outputting white.
- `float circles(vec2 uv, float scale, float thickness)`: Defines a function for repeating circles.
- `float d = length(fract(uv*scale) - 0.5);`: `fract` creates repeating grid cells from `0.0` to `1.0`. Subtracting `0.5` shifts the origin to the center of each cell. `length` calculates the distance from the center.
- `return step(d, thickness);`: The `step` function returns `1.0` if `d < thickness`, creating a solid circular mask.
- `float stripes(...)`: Defines moving stripes.
- `return step(0.5, fract(uv.x * freq + t));`: Multiplies `uv.x` by frequency, adds time, wraps it to `[0,1]`, and uses `step` to output `1.0` on half the wrapped domain, creating alternating vertical bands moving right.
- `vec3 col = mix(vec3(0.1), vec3(1.0), c * circ + stripe * 0.3);`: Combines the masks by multiplying `c` and `circ` (checkerboard only inside the circles), adds the stripes, and uses the result to blend between dark gray and white.

### CS lens
Mathematical space division converts continuous coordinates into discrete zones using functions like `floor`, `mod`, `fract`, and `step`. This avoids the aliasing and scaling artifacts inherent in rasterized image files, yielding infinite-resolution graphics.

### SE lens
Using `step` instead of `if` statements avoids branching inside the shader. GPUs execute instructions in parallel across thousands of fragments; branching (`if/else`) forces groups of fragments to evaluate both paths, harming performance. Using mathematical step functions keeps the instruction pipeline linear.

## Concept Unit: Texture sampling in a custom shader

### The Problem
Sometimes pure math isn't enough; you need the detail of a photograph, but you want to distort or animate it dynamically in ways static geometry cannot. How do we pull an external image into our custom shader and manipulate its coordinates?

### Introduce the concept in isolation

    <script type="module">
        import * as THREE from 'https://unpkg.com/three@0.150.1/build/three.module.js';

            const material = new THREE.ShaderMaterial({
                uniforms: {
                    uTexture: { value: tex },
                    uTime:    { value: 0 },
                },
                vertexShader: `varying vec2 vUv; void main(){vUv=uv;gl_Position=projectionMatrix*modelViewMatrix*vec4(position,1.0);}`,
                fragmentShader: `
                    uniform sampler2D uTexture;
                    uniform float uTime;
                    varying vec2 vUv;
                    void main() {
                        vec2 distortedUv = vUv;
                        distortedUv.x += sin(vUv.y * 10.0 + uTime) * 0.05;
                        distortedUv.y += cos(vUv.x * 10.0 + uTime) * 0.05;

                renderer.render(scene, camera);
                requestAnimationFrame(animate);
            }
            animate(0);
        });

</body>
</html>

## Concept Unit: RawShaderMaterial — no automatic Three.js uniforms

### The Problem
When you use `ShaderMaterial`, Three.js automatically prepends lines like `uniform mat4 projectionMatrix;` and `attribute vec2 uv;` to your shader code. While convenient, this hidden inclusion can cause conflicts or overhead when writing strictly compliant WebGL2 shaders or porting complex external GLSL. How do we take absolute control of the shader string sent to the GPU?

### Introduce the concept in isolation
We will construct a plane using `RawShaderMaterial`, manually supplying all necessary matrices.

```html
<!DOCTYPE html>
<html>
<head><title>RawShaderMaterial Isolation</title></head>
<body>
    <script type="module">
        import * as THREE from 'https://unpkg.com/three@0.150.1/build/three.module.js';
        const renderer = new THREE.WebGLRenderer();
        renderer.setSize(window.innerWidth, window.innerHeight);
        document.body.appendChild(renderer.domElement);
        const camera = new THREE.PerspectiveCamera(75, window.innerWidth/window.innerHeight, 0.1, 100);
        camera.position.z = 2;
        const scene = new THREE.Scene();
        
        const material = new THREE.RawShaderMaterial({
            uniforms: {
                uProjectionMatrix: { value: camera.projectionMatrix },
                uModelViewMatrix:  { value: new THREE.Matrix4() },
                uTime:             { value: 0 },
            },
            vertexShader: `
                precision mediump float;
                attribute vec3 position;
                attribute vec2 uv;
                uniform mat4 uProjectionMatrix;
                uniform mat4 uModelViewMatrix;
                varying vec2 vUv;
                void main() {
                    vUv = uv;
                    gl_Position = uProjectionMatrix * uModelViewMatrix * vec4(position, 1.0);
                }
            `,
            fragmentShader: `
                precision mediump float;
                uniform float uTime;
                varying vec2 vUv;
                void main() {
                    gl_FragColor = vec4(vUv, sin(uTime)*0.5+0.5, 1.0);
                }
            `,
        });
        const mesh = new THREE.Mesh(new THREE.PlaneGeometry(2, 2), material);
        scene.add(mesh);
        
        function animate(time) {
            mesh.updateMatrixWorld();
            material.uniforms.uModelViewMatrix.value.multiplyMatrices(
                camera.matrixWorldInverse, mesh.matrixWorld
            );
            material.uniforms.uTime.value = time * 0.001;
            renderer.render(scene, camera);
            requestAnimationFrame(animate);
        }
        animate(0);
    </script>
</body>
</html>
```

This renders a plane transitioning through colors without relying on Three.js's magic shader injections.

### Mechanical walkthrough
- `new THREE.RawShaderMaterial(...)`: Creates a material that disables Three.js's automatic `#include` system.
- `uProjectionMatrix: { value: camera.projectionMatrix }`: Explicitly defines the uniform for the camera's lens math.
- `uModelViewMatrix: { value: new THREE.Matrix4() }`: Explicitly defines the uniform for the object's transform relative to the camera.
- `precision mediump float;`: In raw WebGL, you must declare float precision. Three.js usually does this for you. `mediump` balances performance and accuracy.
- `attribute vec3 position;`: Explicitly declares the incoming vertex coordinate stream. Three.js normally injects this silently.
- `attribute vec2 uv;`: Explicitly declares the texture coordinate stream.
- `uniform mat4 uProjectionMatrix;` / `uniform mat4 uModelViewMatrix;`: Declares the matrices inside the shader code itself.
- `gl_Position = uProjectionMatrix * uModelViewMatrix * ...`: The standard vertex transformation, but using our explicitly named variables.
- `mesh.updateMatrixWorld();`: Forces the mesh to calculate its absolute position in the 3D scene.
- `material.uniforms.uModelViewMatrix.value.multiplyMatrices(...)`: We must manually compute the ModelViewMatrix each frame by multiplying the camera's inverse transform with the mesh's transform, because Three.js is no longer feeding the hidden `modelViewMatrix` uniform automatically.

### CS lens
Using raw shaders strips away the middleware abstraction, exposing the raw graphics pipeline. WebGL expects pure GLSL. A framework's convenience features (like auto-bound matrices) trade transparency for speed of development. Bypassing them ensures that what you see in the source string is exactly what executes on the GPU.

### SE lens
While `RawShaderMaterial` offers maximum explicit control, it tightly couples your rendering loop to the mathematical setup of individual meshes. In a large project, manually updating ModelView matrices for every mesh breaks encapsulation. It is typically reserved for highly optimized, single-object effects like a full-screen post-processing quad.
