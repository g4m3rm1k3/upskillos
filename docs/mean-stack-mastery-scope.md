# MEAN mastery: required coverage and evidence

This is the expanded scope requested on October 15, 2026. The learner knows basic JavaScript and needs deliberate practice. The existing task-board lessons are the first application milestone, not completion of this curriculum. Nothing in this document marks an unwritten lesson as available.

The target is independent competence in designing, implementing, testing, securing, deploying and operating a MEAN application, with database design as a continuous discipline. Memorizing every API is not a finite or useful completion criterion. Knowing the mechanisms, recognizing failure modes, evaluating alternatives and finding the relevant primary documentation are required.

## How to read the coverage status

- **Practiced:** an authored guided experiment exists; this does not certify mastery.
- **Introduced:** a concept appears, but lacks sufficient independent practice or depth.
- **Required, not authored:** a mandatory part of the expanded path, still to be implemented and verified. It must not be presented as an optional bonus or a completed chapter.
- **Mastered:** a learner-specific claim requiring the evidence below. The repository cannot assign this label merely because reference solutions pass.

## Project progression

Keep the first local task board small so every layer becomes visible. Then evolve it deliberately rather than replacing it with an unrelated code dump:

1. **Local board:** validated titles, one project, persistent tasks, versioned edits and a browser UI. This is the currently authored first-app path.
2. **Designed workspace:** projects, members, tasks, comments and history; explicit relationship/deletion rules, realistic query fixtures, reports and justified indexes. Introduce strict TypeScript at boundaries and service/repository separation.
3. **Secure collaboration:** verified identity, sessions, tenant membership and permission checks, routed Angular screens, typed reactive forms and adversarial tests. No public deployment before these gates.
4. **Reliable service:** idempotent commands, transactions when invariants span documents, background jobs, live updates, cancellation and operational instrumentation.
5. **Operated release:** staging deployment, CI, load evidence, migrations, rollback, backup restoration and an incident drill.
6. **Independent transfer:** select a different domain (for example equipment reservations), derive its invariants and build it without importing the board's implementation. Similar CRUD screens do not establish transfer if the concurrency and ownership rules differ.

Stages B–F need smaller prerequisite lessons before the corresponding production features. Do not expect a beginning JavaScript learner to absorb TypeScript, RxJS, authentication and transactions from one large component.

## Definition of a complete lesson

Every required topic must have a concrete problem, first-use definitions, a worked trace, a runnable small example, a prediction, an intentionally broken case, a repair, an independent exercise with progressive hints, and a check with stated limits. Where automatic grading is appropriate, verify a reference answer and plausible wrong answers. Put infrastructure in supplied files, but never hide the mechanism being taught inside infrastructure.

Each lesson records its prerequisites and what files it changes. Preserve published lesson and step ids. A code sample that runs is not enough: inspect rendered teaching content and verify the learner can reach its cells/files/checks. Avoid teaching frameworks through unexplained full-file replacements.

## Mastery evidence and review cadence

For each stage, retain:

- **Explain:** describe the mechanism and trace a concrete input without the reference.
- **Build:** implement a small variation from requirements, with no supplied solution.
- **Debug:** locate and repair a planted defect, explaining why the repair works.
- **Test:** supply a new counterexample and a test that fails before the repair.
- **Defend:** compare a plausible alternative and state its tradeoffs.

Revisit a prior concept in the next work session and again in a later mixed exercise. If recall fails, repeat a smaller experiment instead of silently skipping the prerequisite. These are recommended learning checkpoints, not UI locks or a claim that a fixed number of days creates mastery. Reading ahead stays available.

Keep `evidence/mastery.md` in the learner project with topic, current status, dated evidence links, unresolved questions and the next practice task. A learner cannot mark a stage mastered merely by copying reference files or passing a file-existence check.

## Release gates and explicit remaining work

The curriculum is incomplete until every required row has authored, reviewed and verified lessons and the capstone can be completed by a learner at the stated entry level. The existing security/deployment “optional extension” wording must not define the expanded course's end state. Those topics are required later work; the current prototype still must not be represented as secure or production-ready.

The advanced lessons are not yet authored. This document is the coverage contract and backlog, not a substitute for those lessons.
